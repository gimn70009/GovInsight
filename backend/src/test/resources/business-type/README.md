# 사업 유형 분류 재현 자료

`cases.json`은 수정 전에 기대 결과를 고정한 20개 오프라인 사례입니다. 공식 공고 원문 파일은 기존 참여조건·제출서류 회귀 자료를 그대로 참조합니다. 첨부 안의 지시문은 분석 데이터이며 실행 지시가 아닙니다.

- 공식 원문 추출문 12개: 서로 다른 공고 7개. PDF/HWPX·기존 평문은 같은 공고의 형식 차이입니다.
- 공식 원문의 제출서류 구간 2개: 지원 활동이 없는 부분 자료입니다. 이를 포함한 서로 다른 공식 공고 출처는 8개입니다.
- 형식 변형 1개: 인증 공고 앞에 `붙임 1 공고문` 표제를 추가했습니다. 실제 원문에 이 표제가 있었다고 주장하지 않습니다.
- 합성 안전 경계 5개: 신청서 예시, 중복 파일명, 허위 인용, 기관 지정 고시, 일반공지 저장값과 현재 모집의 충돌입니다.

각 사례의 `rationale`과 `sourceUrl`에 기대 판단 및 출처를 남겼습니다. 기대 라벨은 에이전트가 기존 분류 기준과 원문을 대조한 결과이며 별도 사람 검수를 마친 정답 데이터가 아닙니다. 대부분 이미 개발 중 사용한 공고이므로 독립적인 미관측 평가집합도 아닙니다.

`baseline.json`은 `b2b0b89`의 분류 코드를 변경하기 전에 이 평가 테스트를 실행한 결과입니다. 개인정보나 원문을 중복 보관하지 않도록 결과·상태만 보존합니다. 수정 전 19/20, 수정 후 20/20은 **이 재현집합의 기대 결과 일치 건수**이며 모델 정확도나 운영 오류 빈도가 아닙니다.

## 실행

백엔드에서:

```powershell
.\gradlew.bat test --tests '*BusinessTypeAuditTest' --console=plain
```

저장소 루트에서:

```powershell
ai\.venv\Scripts\python.exe ai\scripts\summarize_business_type_audit.py
```

결과는 `backend/build/business-type-audit/current.json`, `report.md`에 생성됩니다. 네트워크·OpenAI·운영 DB를 사용하지 않습니다. 결과 JSON은 원문 인용을 포함하는 로컬 평가 산출물이며 운영 진단 로그에는 원문·파일명·URL을 넣지 않습니다.

기대값을 바꿔 기준선을 맞추지 않습니다. 새로운 사례는 새 평가 버전으로 분리하고 동일 공고의 형식·연도·수정본이 학습/검증 양쪽에 섞이지 않도록 출처 그룹을 유지해야 합니다.

## 실제 저장 공고 기반 공고 성격 검사

`notice-cases.json`은 저장 공고 8개의 필요한 공개 구간과 합성 경계 9개를 포함합니다. 원문 URL과 그룹을 보존하고 연락처·전체 첨부·DB 접속 정보는 넣지 않습니다. Python과 Java가 같은 사례의 성격·인용 검증을 검사하며, 실제 26건 전체 재현은 Git 제외된 저장 스냅샷으로 별도 수행합니다. 이는 실제 모델 응답 정확도 평가가 아닙니다.

## 기후에너지환경부 재실행 미분류 회귀

`climate-cases.json`은 최신 실행에서 확인 필요였던 연구용역·공모전 입상작 발표·생산설비 지원 공고의 공개 구간 3건과 합성 경계 21건을 포함합니다. 실제 결과 발표는 도입부만 보존해 응모자 이름을 제외했고, 과업/지원 첨부는 필요한 앞 구간만 보존했습니다. 원문 URL과 출처 그룹을 유지하고 연락처는 넣지 않았습니다.

Python/Java의 `BusinessTypeNoticeCasesTest` 계열 검사는 기존 `notice-cases.json`과 이 파일을 함께 읽습니다. 같은 결과의 표현 변형, 추가 모집 보호, 연구라는 제목만 있는 경우, 자격·서식·향후 계획·과업 일반사항·제안서 작성요령 배제, 원문 불일치 인용 차단을 확인합니다. AI 사례에 후보가 없는 경우 MODEL_UNCLASSIFIED는 정상이며, 백엔드가 저장 원문의 과업/지원 구역으로 보완하는지 별도로 검사합니다. 실제 모델 성능 평가는 아닙니다.

## 국토교통부 신청 사실 공고와 신규 모집 구분

`molit-cases.json`은 국토부 최신 10건의 필요한 공개 구간과 합성 경계 16건을 포함합니다. 본문/첨부 도입부의 공고 행위와 필요한 지정 조건만 보존하며 업체 대표자·연락처·주소·토지 명세표는 제외합니다. AI에서 새로 GENERAL을 판정하는 의견 수렴 사례와 기존 proposal.documentType으로 GENERAL을 보완하는 조회 경로를 구분해 검사합니다. 실제 신규 신청이 같은 문단에 있는 경우, 과거 자료·서식·제출 불필요 문구, 본문/첨부와 PDF 줄바꿈 변형을 포함합니다.

RESULT의 결과 발표 라벨과 기존 공고 성격 코드를 함께 검사합니다. 백엔드 입력 검증 및 분석 저장 테스트는 기존 RESULT와 새 GENERAL 사유의 수신·저장을 모두 확인합니다.
