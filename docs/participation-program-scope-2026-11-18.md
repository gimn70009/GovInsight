# 통합공고 사업명 연결 수정·검증 (2026-11-18)

## 원인과 구현

2027년 스마트 제조혁신 지원사업 통합공고(version_id=6)의 기존 18조건 중 scope가 있는 6개 모두 신청 대상 또는 참여 형태였다. 생성 시점의 group_label에는 실제 사업명이 남아 있었다. 프런트는 서버 scope를 그대로 표시했고, 기존 검증은 인용 존재를 검사하되 인용의 사업명과 scope를 연결하지 않았다. 정부일반형·제조AI특화 문단은 추출됐으나 12구역 선택 상한에서 제외됐다.

- 프롬프트에서 사업명/신청 역할을 구분하고 통합·사전안내 공고의 사업별 대상을 유지하도록 명시했다.
- 입력 선택은 동일 우선순위에서 아직 포함하지 않은 사업을 먼저 선택하고, 최대 24구역을 같은 원문 8,000바이트·전체 요청 20,000바이트 안에 넣는다. 과도한 문맥까지 포함한 직렬화 예산을 초과하면 해당 후보를 제외하고 다른 후보를 검토한다.
- Java는 원문 인용 위치로 사업명을 검증한다. 실제 표의 세부 사업/유형은 유지하며, 애매한 인용을 첫 사업에 배정하지 않는다. 마지막 표 행 인용 뒤에 다음 사업 제목만 붙은 경우 연결에만 표 범위를 사용한다.
- 다른 사업의 자격이 공통 조건 설명에 묶였더라도 각 인용의 사업이 분명하면 해당 사업의 독립 항목으로 표시한다. 인용·문장·같은 사업의 정의/예외는 보존한다.
- 괄호의 신청 역할도 복원한다. 특정 공고명이나 제조기업·컨소시엄 같은 단어의 금지 목록을 제품 코드에 넣지 않았다.

## 비용

모델 gpt-5-mini·low, 문서당 최대 1회, 자동 재시도 0회, 출력 4,096토큰과 캐시 v6를 유지했다. 다른 공고의 저장 결과를 무효화하지 않는다.

| 제조 통합공고 원문 바이트 | 7058 | 7968 |

프롬프트·출처·strict 스키마를 포함한 o200k_base 로컬 직렬화 계산이다. 통합공고 입력은 약 14.8% 증가하며 누락 사업의 자격 문단을 포함한다. 실제 청구 입력/출력과 캐시 할인은 다를 수 있다.

실제 모델 검증은 1회만 실행했다. 입력 4,803·출력 2,916·합계 7,719토큰이며 finish_reason=stop이었다. 추가 유료 재시도는 없었다. 원응답 16조건은 일부 사업을 공통 details에 묶고 scope를 컨소시엄으로 반환했다. 최종 서버 코드로 같은 원응답을 재생하면 정부일반형·제조AI특화가 독립 항목이 되고 잘못된 배지가 제거된다. 그 외 원응답의 역할 혼합·제외 사유 통합 등을 그대로 운영 결과로 채택하지 않았다. 통합 사전안내에 대한 마지막 문구 보완 이후 추가 실모델 호출은 하지 않았다.

## 해당 공고 데이터 보정

기존 18개 조건의 본문·설명·인용을 보존하고 scope와 두 신청 역할을 원문에 맞췄다. 신규 결과 중 원문에 맞는 미포함 사업과 직접 확인한 사업별 지원 대상을 합쳐 14조건을 추가해 총 32조건으로 보정했다. 정부일반형·제조AI특화, 상생형, 자동화 지원, DX멘토단, 고난도공정 로봇자동화, 피지컬AI 세부 실증 등이 독립 사업으로 표시된다. 이 개별 원문 검토는 모델 자동 생성 성공과 구분한다.

백업, SELECT FOR UPDATE, 기존 제목·수집 시각·전체 저장 JSON·키 비교를 거쳐 participation_rewrite_json 1행만 갱신했다. 저장 후 다시 읽어 결과와 키 보존을 확인했고, 원문·첨부·다른 공고·제출서류 캐시는 바꾸지 않았다. 기존 미검토 근거를 일괄 '무관'으로 변경하지 않았다.

## 검증

- 최종 백엔드 전체: 1,799개 통과, 실패·오류·건너뜀 0.
- AI 참여 조건·제출 관련: 409개 및 변경 파일 Ruff 통과.
- 프런트 사업 배지·필터 관련 26개와 build 통과.
- 실제 저장 데이터와 실제 모델 응답을 서버 코드로 재생하고 캐시 키 동일 확인.
- 대체 GET API를 사용한 브라우저 1440/390/320px: 32조건, 올바른 사업 배지, 정부일반형·제조AI특화·클라우드 필터별 8조건(개별 1+공통/제외 7), 원문 펼치기, 가로 넘침 없음.
- 중간 전체 검사에서는 기존 ProposalDraftPersistenceTest의 마지막 조회 순서 검사 1개가 실패했으나 최종 전체 재실행은 통과했다.

표 구조와 제목이 불명확한 문서는 임의로 사업을 추정하지 않는다. 고정 예산 안에서 모든 대형 통합공고의 모든 조건을 추출한다고 보장하지 않으며, 원문 검토가 필요한 근거는 유지한다. 화면 검증은 실제 서버 로그인 없이 저장 결과를 재생한 것이며 모델 의미 정확성의 전면 보장은 아니다.

입력 비교·원응답·재생 결과·DB 전후 백업·검사 로그·화면은 Git 제외 `backend/build/smart-scope-fix-20261118/`에 보관한다.

최종 정리: 검증용 4197 프로세스를 종료했고 8080·4197 포트가 비어 있음을 확인했다. 별도 읽기 전용 DB 연결에서도 version_id=6의 저장/표시 32조건 및 캐시 키 동일을 다시 확인했다.

## 커밋 대상 분리 검증

제출서류·사업 분류 등 별도 미커밋 변경을 제외한 Git 인덱스 복사본에서 AI 신청 자격 373개와 백엔드 신청 자격 349개가 통과했다. 백엔드 전체 1,765개 실행에서는 로컬 설정을 포함하지 않아 JWT 유효기간 설정이 누락된 통합 테스트 9개와 기존 초안 조회 순서 테스트 1개가 실패했다. 테스트 프로세스에 `APP_JWT_ACCESS_TOKEN_EXPIRATION=1h`를 지정하고 실패한 세 테스트 클래스를 별도로 재실행해 18개 모두 통과했다. 추가 유료 API 호출은 없으며 관련 없는 작업 파일은 그대로 남겼다.
