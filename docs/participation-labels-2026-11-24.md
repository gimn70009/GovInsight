# 적용 사업·신청 구분 오류 수정

## 확인한 원인

2026-11-24 수집된 총괄주관연구개발기관 공고(version_id=12)의 저장된 AI 응답에 `사업 개요 - 지원분야`, `사업 개요 - 수행내용`, `총괄주관연구개발기관 모집 공고 / 자격 확인서`가 scope로 들어 있었다. 현재 Java 표시 결과에서도 동일하게 남았다. 원문 구역명과 모집 제목을 모델이 자유 문자열로 작성했고, 단독 구역명만 제거하던 후처리가 복합 경로·서식명을 통과시켰다. 모델 원응답은 별도로 보관되지 않아 저장된 검증 후 응답과 코드를 대조했다.

기존 프롬프트에는 사업/유형과 신청 주체를 구별하는 지시가 이미 있었다. 이번 변경은 신규 프롬프트 보완과 함께 기존 저장 결과의 표시 검증을 수정한다.

## 변경

- 모집 제목과 구역/서식 이름으로만 이루어진 경로를 사업 라벨에서 제외한다. `성장사업 · 사업 개요 - 지원분야 / 도약사업`은 `성장사업 / 도약사업`으로 남긴다. 실제 이름에 포함된 `소재·부품·장비`, `A-B형`, `사업 개요 작성 지원사업` 등은 보존한다.
- Java 원문 문맥 보정 전후에 사업 라벨을 검사하여 잘못된 저장값의 재사용과 보정 후 재유입을 막는다. request와 캐시 식별 계산은 바꾸지 않는다.
- 신청 구분은 해당 조건의 인용문에 있는 어휘만 허용하고, Java는 직접 연결된 자격표 행·괄호 역할을 우선한다. 다른 행에 있는 명칭이나 모델 본문 자체를 새 근거로 쓰지 않는다. 근거 없는 라벨은 생략하되 조건 본문·인용·상세는 보존한다.
- `신청기관(기관 및 개인)`의 부정확한 기관 수식은 인용에 있는 `기관 및 개인`으로 정리하고, `기업 신청자`는 인용에 있는 `기업`으로 정리한다. 연구책임자·참여연구자 등 개인에게 적용되는 제외 조건의 라벨은 근거가 있으면 유지한다.
- 신규 Python 결과에도 같은 라벨 기준을 적용한다. 프롬프트와 필드 설명은 인용의 주체, 구역 경로·서식명 금지, 근거 없으면 null을 명시한다. 모델·추론 설정·호출 수·재시도·출력/입력 상한은 유지한다.

## 실제 저장 결과 재생

Oracle은 읽기 전용 트랜잭션으로 조회했으며 현재 Java 표시 함수를 적용했다. 제보 공고의 9조건 모두 본문·request·캐시 JSON·저장 키가 수정 전후 일치했다. DB 쓰기와 실제 모델 호출은 하지 않았다.

원본/수정 표시 재생 자료는 Git 제외 `backend/build/eligibility-labels-20261124/`에 보관한다. 조건의 의미 정확성이나 누락을 이번 라벨 수정의 성과로 계산하지 않는다.

## 검증 범위

AI 신청자격 테스트 452개, 백엔드 전체 테스트 1,844개가 통과했다(실패·오류·건너뜀 0개). 실제 사업명·다중 사업·다른 행의 주체·개인 제외 조건·복합 구역 경로와 조건/인용 보존을 검사했다. 프롬프트 3,600바이트와 직렬화 입력의 기존 회귀 상한도 통과했다. 변경 Python Ruff와 diff 검사 통과, 마무리 시 8080 비점유를 확인했다.

새 프롬프트의 실제 모델 생성, 브라우저에서의 재접속은 수행하지 않았다. 기존 저장 응답을 제품 표시 함수로 재생한 결과이며 실제 생성 품질 개선을 보장하지 않는다. 어휘 근거 검사는 완전한 의미 판별이 아니고 원문과 표현이 크게 다른 유효한 라벨도 생략할 수 있다. 본문과 근거는 남아 있다.
