## 수정 내용과 원인

건설신기술 지정 신청 공고는 AI의 proposal.documentType=GENERAL_NOTICE였지만 제목에 ‘신청’이 있어 백엔드의 신규 모집 보호 규칙이 일반공고 보완을 막았습니다. 본문에는 지정신청이 이미 있다는 선언과 이해관계인 의견서 제출 요청이 명시돼 있습니다. 30일은 이 의견 제출 기간이며 신규 지정 모집의 근거로 쓰지 않았습니다. 기한 등 다른 표시 필드의 동작은 변경하지 않았습니다.

신청 사실과 의견 요청을 원문 도입부에서 함께 확인하는 공통 규칙을 Python/Java에 추가했습니다. 제목만 있거나 서식·과거 사례만 있는 경우에는 추정하지 않습니다. 별도의 새 신청·모집·사업계획서 제출 요청이 같은 공고에 있으면 실제 모집을 보존합니다. 기관명·문서 ID·공고명 예외를 넣지 않았습니다.

RESULT 코드는 기존처럼 유지하며 표시를 ‘일반 공고 · 선정 결과’에서 ‘일반 공고 · 결과 발표’로 바꿨습니다. 골재채취능력평가는 선정 여부 발표가 아니므로 넓은 문구가 적합합니다. 웹과 새로 생성/재전송하는 이메일에서 동일한 라벨을 씁니다.

새 검증 사유 NOTICE_GENERAL과 noticeKind=GENERAL을 AI 스키마 및 백엔드 수신 검증에 함께 반영했습니다. 검증 버전은 business-type-v4-opinion-notice이며 기존 비교 요약 JSON에 저장합니다. 원문 인용 일치 검사는 완화하지 않았습니다.

## 검증과 적용

- 현재 35건 재현에서 상태·유형 코드·공고 성격 변화는 버전 44 하나뿐입니다. 다른 결과 공고는 RESULT 코드가 유지되고 표시 문구만 바뀝니다.
- 이전 기후부 스냅샷 28건 및 이전 저장 스냅샷 26건의 분류는 유지됩니다. 스냅샷 간 중복을 새로운 정확도 표본으로 합산하지 않습니다.
- 국토부 실제 공개 구간 10건·합성 경계 16건을 Python/Java 공통 자료에 추가했습니다. 백엔드 입력 검증·저장과 웹/메일 라벨 회귀도 검사합니다.
- 최종 전체 테스트: 백엔드 1,120개(실패·오류·건너뜀 0), AI 1,878개, 웹 53개 통과. 변경 Python Ruff와 `git diff --check`도 통과했습니다.
- 작업 종료 시 8080 포트에 리스닝 프로세스가 없음을 확인했습니다.
- 백엔드 재시작 후 기존 공고 상세 조회와 새 이메일 렌더링에 적용됩니다. 해당 1건의 표시 개선에는 재수집·재분석이 필요하지 않습니다. 새 AI 지침/검증 사유는 AI 재시작 후 새 분석부터 적용됩니다.
- 실제 OpenAI·SMTP 호출, 운영 데이터 수정, 인증된 실제 브라우저 화면 확인은 하지 않았습니다. 원문 전수 조회와 저장 자료 재현, 테스트 대체 응답으로 검사했습니다.
- 개인정보가 포함될 수 있는 전체 원문 스냅샷과 오프라인 조사 도구는 Git 제외된 backend/build/business-type-audit 아래에만 보관합니다.
