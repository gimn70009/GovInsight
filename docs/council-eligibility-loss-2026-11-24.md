# 광역형 산학연협의체 신청자격 누락 단계 분석

## 범위와 재현 방법

2026-11-24 사용자 화면과 제공 PDF, 현재 저장된 version_id=2의 원문·검증 후 AI 응답을 대조했다. Oracle은 읽기 전용 트랜잭션으로 조회했다. 제공 PDF의 SHA-256은 DB PDF 첨부 해시와 일치한다(`6f0aefd0752eceb488918950265f85f92053110d89086c31ca06bf382dedd626`).

현재 Java 후보·송신 요청과 Python 입력 선별/메시지 생성/검증 함수를 모델 호출 없이 재생했다. 캐시 키도 현재 request와 일치한다. 실제 생성 당시의 전체 모델 입력·원응답은 보관되어 있지 않으므로 현재 코드로 재구성한 입력과 저장된 검증 후 응답을 구분한다. 앞선 라벨 수정의 미커밋 제품 코드는 이번 분석에서 변경하지 않았다.

원본 및 재현 도구는 Git 제외 `backend/build/council-stages-20261124/`에 있다. `snapshot.json`, `model-input.json`, `sources.json`, `trace.txt`, `probes.txt`, `SourceGateAudit.java`, `bonus_probe.py`로 재현했다. 운영 DB 쓰기와 실제 모델 호출은 0회다.

## 1. 신청제한 조항: Java 입력 후보 필터에서 탈락

PDF 11쪽의 `주관기관이 ... 사전지원제외대상에 해당하는 경우 신청 및 참여를 제한`은 저장 원문과 rawGuide에 존재한다. 하지만 `ParticipationFocusCriterion.matching`은 빈 목록을 반환한다. 신청 주체를 뜻하는 모든 기관을 받는 것이 아니라 중소기업·법인·단체 등 7개 항목의 제한된 어휘를 찾기 때문이다.

`ParticipationRewriteProjection.input`은 matching이 빈 출처를 기본 request에서 제외한다. 보충 경로의 `ParticipationSourceSelection`도 자격·대상·요건·조건·우대·가점 제목만 인정해 `신청제한에 관한 사항`을 복구하지 않는다. 실제 두 원문 형식에서 matching=[], explicit=false, compatible=false를 재현했다. 따라서 프롬프트의 “법적 등록·허가·참여제한은 보존” 지시와 달리 모델에 도달하지 않는다.

## 2. 주관·공동주관기관 자격: Python 문단 선별에서 잘림

`s7`은 930자로, 주관기관 유형별 법적 자격표와 공동주관기관·연계 비즈허브·참여 기업/기관·지역 정의를 모두 담고 있다. `selection.prepare`가 `requirements.context_excerpt`를 거치면서 참여 기업 및 기관 문단과 그 주석 157자만 남긴다.

주관기관 유형 목록과 공동주관기관 지정 문단에는 기존 condition_context 패턴의 가능·필수·역량 등의 표현이 없고 `(주관기관)`도 applicant_labels에서 인정하는 신청/참여/지원 대상·자격·요건 형식이 아니다. 반면 `(참여 기업 및 기관)`은 참여 기업 패턴에 걸린다. 해당 구역에서 모든 조건을 다루라는 프롬프트와 달리 필요한 원문 자체가 선별에서 제거된다.

주관기관 자격표의 `설립 근거 등` 헤더도 qualification_rows의 자격·요건·조건 목록에 없다. 원문을 살려 보내더라도 현재 표 행 누락 검사가 자동으로 이 표를 인식하지 못하는 별도 문제가 있다.

## 3. 광역지자체 수·성장엔진·지역산업진흥원: 생성 누락을 검증이 놓침

### 광역지자체 수와 성장엔진

`s0`의 97자 원문은 그대로 선택된다. 저장된 첫 조건의 supporting_quotes에도 `5극3특 권역별 성장엔진`, `2개 이상의 광역지자체`, `2개 이상의 산단`이 모두 있다. 그런데 본문과 details에는 광역지자체 수와 성장엔진 조건이 빠졌다. 현재 표시 변환이 삭제한 내용이 아니라 저장 응답부터 없는 내용이다.

`completeness.quantities`는 숫자·단위 쌍을 집합으로 만든다. 원문의 서로 다른 대상인 광역지자체 2개와 산단 2개가 모두 ('2', '개') 한 항목으로 합쳐진다. 요약의 산단 2개만으로도 row_values_preserved=True가 된다. 대상·비교어·반복 횟수는 검사하지 않는다. `quantity_review`도 명시적 표 행 하나를 인용한 경우만 검사해 일반 문단인 s0에는 작동하지 않는다.

### 지역산업진흥원 필수 참여

`s8`의 967자 원문과 저장된 네 번째 조건 인용문에는 `주관지역의 지역산업진흥원 필수 참여`가 있다. 본문·설명에는 없는데 `coverage.covered`는 해당 원문 L16을 True로 판정한다. 인용 포함 여부와 수치 보존을 확인할 뿐 이 문구가 요약에도 표현됐는지 확인하지 않으며, 이 구절은 검사 대상 수치가 없어 수치 검사를 통과한다.

신청자격 표는 첫 구성요건 부분이 `[표]`와 탭 행이 없는 일반 줄로 전달된다. `required_rows`는 0개이며 inventory가 잡는 구간도 앵커기업·그 정의·지역산업진흥원 3개뿐이다. 그중 정의는 누락으로 잡지만 지역산업진흥원은 잘못 covered 처리한다. 완전한 요건 목록 검사가 아니다.

## 4. 가점: 표 구조와 인용 계약 충돌

가점은 `s10`의 선택된 원문에 존재한다. HWPX 추출 표의 병합 셀이 반복되면서 가점·법적 정의가 하나의 947자 물리적 행(L13)에 들어 있다.

현재 추출 스키마는 인용을 L13 또는 L13-L14처럼 줄 번호로만 받으며, `focused.project`는 해석한 실제 인용이 600자를 넘으면 QUOTE_TOO_LONG으로 해당 조건 전체를 제외한다. L13을 인용하는 정상 가점 문장을 모의 입력하니 수용 0, QUOTE_TOO_LONG=1로 재현됐다. 모델이 행 안의 일부 셀만 인용할 수 있는 계약이 없다.

저장 진단에도 QUOTE_TOO_LONG=1이 있지만 원응답은 없으므로 거절된 실제 후보가 가점이었다고 단정할 수는 없다. 가점 행을 현재 계약으로 정상 인용할 수 없다는 충돌은 확인했다. 가점 표는 qualification_rows와 inventory에도 잡히지 않아 가점 누락 자체에 대한 독립 경고가 없다.

## 5. 실제 실행 프롬프트와 별도 검증 프롬프트의 차이

이 요청은 7개 분류가 있는 focused 계약이므로 `service.rewrite`에서 즉시 `extract_focused`로 간다. `prompts.py`의 REWRITE/VERIFY를 실행하는 일반 경로가 아니다. 실제 그래프는 extract → source_check → END이며 추가 모델 검증이나 보완 재시도가 없다.

일반 프롬프트에는 의무·예외를 같은 문장에 두고 다른 statement에만 있으면 거절하라는 규칙이 있다. 하지만 실제 focused 프롬프트는 `details는 본문에 없는 ... 예외 ...`를 허용한다. 따라서 전문가 2개 가입 제한의 예외가 접힌 설명에만 남는 것은 모델이 모든 지시를 단순히 어긴 것으로 볼 수 없다. 접힌 본문만으로 정확히 읽히게 하려는 화면 요구와 실제 사용 지시의 정합성이 부족하다.

반복 설명은 focused 프롬프트에서도 금지하지만 별도의 의미 중복 검증을 수행하지 않는다. 원문 인용·문장 형식·일부 법령/제재 검사 통과가 프롬프트 전체 준수를 의미하지 않는다.

## 6. 화면과 분류·사업 라벨의 영향

이번 7개 조건은 저장 응답부터 7개이며 Java도 7개를 표시한다. 본문 주요 누락을 프런트가 삭제해서 만든 것은 아니다. 프런트는 VERIFIED만 조건으로 보여주고 EVIDENCE_ONLY와 REVIEW_REQUIRED는 표시하지 않는다. PARTIAL 전체 안내는 있지만 빠진 구절을 개별적으로 알려주지는 않는다. 미완료를 인지해도 자동 복구하지 않는 구조다.

실제 사업명 `산업단지 광역형 산학연협의체 구성·운영`은 재구성된 모델 입력에 없었다. scope는 자유 문자열이며 사업명 후보 목록에 연결된 식별자가 아니다. 따라서 `협의체`가 원문에 등장한다는 것만으로 역할·사업 구분이 검증되지는 않는다. 앞선 라벨 수정은 문서 구역/서식명을 제거하는 범위였고 이 의미 혼동은 남아 있다.

선행 약정·민간부담금을 포함하라는 지시와 별개로 출력 항목은 7개뿐이며 자부담/구성요건 전용 분류가 없다. 저장 응답은 민간부담금을 CREDIT에 넣었고 코드도 허용한다. 이는 누락의 직접 증거라기보다 표시 분류가 어색해지는 계약상의 한계다.

## 수정 우선순위

1. 제외·제한·역할별 법적 자격을 입력에 보존하는 후보/문단 선별을 고친다. 제목 키워드만으로 필수 원문을 제거하지 않고 기존 캐시 식별과 새 송신 범위를 분리한다.
2. 반복 병합 셀을 처리하고 원문 위치를 보존한 셀·구절 단위 인용을 지원한다. 600자 상한을 단순히 늘리는 것과 구분한다.
3. 완전성 검사를 인용 존재 여부에서 요건의 주체·수치·비교·필수성·예외가 실제 요약에 남았는지 검사하는 방향으로 바꾼다. 동일 숫자의 다른 대상을 구별한다.
4. 실제 focused 프롬프트에서 본문/예외/설명 분담을 명확히 하고, 누락 발견 후의 복구 또는 사용자 표시 방침을 정한다. 호출·비용 정책 변경은 별도 범위다.
5. 사업명과 신청 주체의 근거 연결, 자부담·구성요건 분류와 반복 설명을 정리한다.

이번에는 분석과 오프라인 진단만 수행했다. 제품 수정, 실제 모델 재호출, DB 보정, 전체 테스트 재실행은 하지 않았다. 이전 테스트 통과를 실제 공고 완전성 보장으로 계산하지 않는다.
