# 제출서류 목록 구조 공통화 검증

## 변경 범위

제출서류 제목의 참조 안내, 계층 번호, 서류명 뒤 주석, 명사형 서류, 다음 절 경계, 묶음의 조건 범위를 일반적인 문서 구조 규칙으로 처리한다. 운영 코드에는 제보 공고명·기관명·특정 서류 목록을 넣지 않았다. 기존 표 추출과 조건·출처 검증을 유지하고 동일 파일의 반복 추출본에서 정확히 일치하는 인용을 첫 출처에 연결한다.

유의사항에는 공통 제출 방식의 범위 지시를 보완하고, 원문에 없는 ‘오직/~만’ 제한을 Python과 Java에서 거부한다. 기존 저장 결과도 Java 검증을 통과해야 표시된다. 모호한 유의사항을 임의의 문장으로 바꿔 저장하지 않는다.

## 검증

- 새 구조 테스트의 수정 전 결과: 16개 중 15개 실패. 묶음 조건 사례를 추가한 최종 구조 테스트 17개 통과.
- 제출서류·표·유의사항 테스트 통과. 기존 유형별 표 근거 회귀 1개를 발견해 보존하도록 수정했다.
- 실제 저장 원문을 DB·모델 호출 없이 재생: 서류 0→5개, AI용 서류 목록 0→5개. 저장 원문·DB 캐시는 수정하지 않았다.
- 실제 원문 재생 결과를 모의 API로 제공해 1440/390/320px에서 5개 목록, 빈 목록 안내 제거, 원문 펼침, 가로 넘침 없음을 확인했다.
- AI 신청 자격·제출서류 테스트 379개 및 Ruff 통과. 프런트 build 통과.
- 백엔드 첫 전체 실행: 1782개 중 기존 ProposalDraftPersistenceTest의 최근 조회 순서 검사 1개 실패. 관련 코드는 이번 변경과 무관하며 수정하지 않았다. 해당 클래스 단독 재실행은 통과했다. 두 번째 전체 실행도 같은 검사 1개가 실패했다. 최종 1782개 중 1781개 통과이며, 제출 관련 109개는 모두 통과했다. 저장 코드의 현재 시각 및 동일 시각 정렬에 대한 의존성을 확인했지만 이번 범위 밖의 코드는 변경하지 않았다. 전체 테스트 성공으로 보고하지 않는다.

## 호출·비용·적용

추가 유료 API 호출 0회. 모델, 추론 수준, 호출 수, 재시도, 출력 상한, API 스키마, 캐시 버전은 그대로다. o200k_base 로컬 비교에서 프롬프트는 1073→1144토큰(+71), 실제 제보 원문의 서류 목록 복구까지 포함한 직렬화 입력은 6592→6945토큰(+5.35%)이다. 이는 입력 규모 비교이며 실제 청구액 측정이 아니다.

목록은 백엔드 재시작 후 현재 원문에서 다시 계산한다. 새 AI 지시는 AI 서비스 재시작 후 생성에 적용된다. 복구된 서류로 입력 지문이 달라진 경우 기존 조회 정책에 따라 유의사항 생성 1회가 발생할 수 있다. 캐시를 일괄 무효화하거나 임의로 DB를 덮어쓰지 않았다. 새 프롬프트의 실제 모델 생성은 검증하지 않았으며 모의 테스트와 구분한다.

검증 파일은 Git 제외 경로 `backend/build/research-security-audit-20261117/`에 보관한다.

검증용 미리보기를 종료했으며 4197·8080 포트가 비어 있음을 확인했다.
