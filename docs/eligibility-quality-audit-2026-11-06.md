### 기술나눔: 캐시, 입력, 추출, 표시를 분리한 원인

1. 캐시: 현재 원문으로 계산한 participation-seven-fields-v3 키와 저장 키가 일치한다. 오래된 캐시를 잘못 재사용한 사례가 아니다. 같은 키의 READY 결과이므로 기존 정책상 재조회만으로 재추출하지 않는다.
2. 첨부: 주 공고문 HWPX는 정상 파싱됐고 자격 문단이 들어 있다. 기술소개서 PDF 1개가 FAILED이지만 이것이 이미 읽은 자격 전체를 숨기는 직접 원인은 아니다.
3. 저장 결과: BUSINESS_FORM/ELIGIBILITY 항목 2개가 모두 원문 검증을 통과한다. 하나는 지원자격과 법적 정의 각주를 통째로 복사한 명사형이고, 다른 하나는 `L1: 신청자격`이라는 제목 조각이다. ParticipationDisplayStatements의 restore가 각주 포함 목록을 거절하고 완결문으로도 인식하지 않아 0행이 된다. `plainQualification`의 표제 제한으로 대체 표시도 만들어지지 않는다.
4. 현재 모델 재실행: 두 후보를 만들지만 본문 quote에 실제 줄바꿈 대신 리터럴 `\n`을 넣었다. 원문 인용 검증에서 1개가 탈락한다. 남은 제목 조각 역시 표시되지 않는다. 캐시를 지우고 같은 설정으로 다시 호출해도 문제가 재현됐다.
5. 추가 입력 누락: 원문에 있는 벤처기업 가점은 `심의 방법 및 기준` 아래 priority 5가 되어 신청자격 구역이 있는 경우 선택되지 않는다. 신용거래 불량 등 제외요건은 `기타 유의사항` 표제가 IRRELEVANT에 걸려 모델 입력 전에 제거된다. 최종 입력은 s5의 제목 조각과 s6의 자격 문단 2개뿐이다. 토큰 한도 소진 때문에 빠진 것이 아니다.

### 기획 검토안 — 미반영

현재 네 열은 자격 항목·필수/우대·해당 사업·조건 문장에 같은 위계를 부여한다. 단일 사업에서도 해당 사업 열의 `-`가 공간을 차지하고, 긴 문장과 근거 버튼이 마지막 열에 몰린다.

검토안은 조건 문장을 중심으로 두고 분류는 작은 제목 또는 문장 위 라벨로 유지한다. 필수·우대·지원 제외는 의미가 분명한 짧은 배지로 구분한다. 실제 세부 사업이 있을 때만 사업명을 붙이고, 유형이 없으면 칸 자체를 만들지 않는다. 여러 사업이 있는데 적용 범위가 불명확한 경우는 단순히 숨기지 않고 확인 필요를 표시해야 한다. 자격의 의미를 바꾸는 예외·기준일은 본문 아래에 노출하고 원문 근거만 접을 수 있게 한다.

데이터 구조도 조건의 자격성·근거와 분류를 분리해야 한다. 자격으로 확인된 조건의 분류만 불명확할 때는 기타 신청요건으로 보존한다. 문의·일정·규정 제목 등 자격으로 확인되지 않은 조각까지 기타 요건으로 노출해서는 안 된다. 시설·소재지·인력 등 현재 7개 분류의 포괄 범위도 별도 검토가 필요하다. 미추출, 인용 실패, 문장 정리 실패, 분류 미확정, 모집 공고 아님을 전부 같은 빈 결과로 표시하지 않는 방향을 권고한다.

대화 내 비교안은 원문을 바탕으로 사람이 정리한 일부 조건 예시이며 실제 LLM 결과나 전체 요건 목록이 아니다. 두 구성·세 공고·밝고 어두운 테마·4개 너비(736/480/390/320px) 48조합과 키보드 근거 열기를 검증했다. 운영 화면 변경이나 추출 문제 수정은 이번 조사에 포함하지 않았다.

### 디자인 검토안

기존 네 열 대신 조건 문장을 중심으로 분류별 묶음을 만들고, 같은 묶음의 조건이 여러 개이면 CSS로 그린 원형 숫자를 붙였다. 한 조건만 있는 묶음에는 번호가 없다. 별도 원문 근거 버튼을 없애고 문장 전체를 native details/summary로 열 수 있게 했다. hover/focus에서는 영역을 강조하고 원문 힌트를 표시하며 모바일에서는 힌트를 항상 표시한다. 독립된 조건별 열기·닫기, Enter/Space와 터치를 지원한다.

### 프롬프트 변경과 비용

실제 전송 경로에서 system 메시지와 구조화 출력 스키마가 모델에 전달됨을 확인했다. 문체 지시가 누락된 문제가 아니라, 현재 모델 설정에서 목록·표를 복사하고 지시를 일관되게 따르지 않는 문제였다.

- 명사형 원문을 완결문으로 바꾸는 예시와 text 필드 설명을 추가했다. 독립요건을 항목별로 작성하되 정의·예외·조건·법령·수치·AND/OR를 유지하도록 했다.
- 분류별 의미를 필드 설명에 넣고 기업규모와 매출, 인력·시설과 신용의 구별을 명시했다. 이 지시가 실제 의미 검증을 대신하지는 않는다.
- quote를 `L2` 또는 `L2-L4` 형태로 생성하도록 제공자 스키마 pattern을 추가했다. 기존 직접 인용의 역호환과 원문 일치 검사는 유지했다. 범위 역전·범위 초과·원문 600자 초과 등은 기존 경로에서 거절된다.
- 문장 종결 정규식은 실제 시험에서 종결어미만 덧붙이는 결과를 만들어 최종 변경에서 제거했다. 원문·백엔드 표시 검증도 완화하지 않았다.
