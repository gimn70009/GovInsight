# 제출 준비 보고서 검증

## 동작

보고서의 전체 첨부 나열을 신청 단계 필수/조건부 서류 중심 목록으로 변경했습니다. 항목은 서류명·원문상 제출 주체·준비 담당 역할(권장)·양식 링크이며 ZIP은 실제 ZIP URL과 내부 파일명을 제공합니다. 근거 파일이 공고문이라고 해서 공고문을 작성 양식에 연결하지 않습니다.

## 검증

- AI 전체: **661개 통과**. 제출 의무가 없는 파일명/ZIP 목록 제외, 근거 인용 대조, 다른 첨부의 근거 혼용 방지, 주관/공동 기관별 동일 서류 유지, 조건부·택1·선택·선정 후 단계 구분, 단일 행 본문 경계, 링크 안전성, 표시/저장 길이 한도를 확인했습니다.
- 백엔드 Gradle 전체: **321개 통과**, 실패·오류·건너뜀 0개. 기존 이메일 호환, 새 제출서류 HTML 카드, 텔레그램 강조, 원문 이스케이프, ZIP 링크 보존을 확인했습니다. 테스트는 H2·대체 외부 연동으로 수행했습니다.
- 프론트엔드: **11개 통과**, 빌드 통과, 린트 오류 0개와 기존 DocumentsPage 경고 2개.
- 실제 Python 템플릿이 생성한 가상 보고서를 `backend/src/test/resources/reports/submission-checklist.txt`에 저장했습니다. Java 렌더러가 생성한 HTML을 `frontend/tests/reportSubmission.browser.py`로 확인했습니다. 5개 서류 카드, 기관 역할, 조건부 표시, ZIP 내 파일명과 URL, 390/320px 가로 넘침 및 스크립트 주입 방지를 검사했습니다. 외부 HTTP(S) 접근은 차단했습니다.
- 웹은 대체 API를 사용하는 `reportDelivery.browser.py`에 동일한 본문을 전달해 카드·링크·모바일 표시 및 기존 수신자 관리를 검증했습니다. 실제 SMTP·텔레그램 발송이나 운영 DB 변경은 수행하지 않았습니다.

## 재현

1. `backend/`에서 `gradlew.bat test` 실행 후 저장소 루트에서 `ai/.venv/Scripts/python.exe frontend/tests/reportSubmission.browser.py`를 실행합니다.
2. 프론트엔드 빌드/4173 프리뷰가 실행 중일 때 `DELIVERY_REPORT_BODY`를 위 텍스트 fixture의 절대 경로로 지정하고 `ai/.venv/Scripts/python.exe frontend/tests/reportDelivery.browser.py`를 실행합니다.
3. 캡처 경로는 `DELIVERY_SCREENSHOT_DIR`로 지정할 수 있습니다.

## 한계

- 파일명이나 기존 모델 판정만으로 제출 의무를 확정하지 않습니다. 복잡한 표·긴 문맥은 추출하지 못할 수 있으며 보고서 전달 한도와 ZIP 파싱 실패/대표 파일 선택의 제약은 유지됩니다.
- 준비 담당은 명시적으로 권장 역할이며 사내 직원 배정 정보가 아닙니다. 서류 종류만으로 실제 책임자를 확정하지 않습니다.
- ZIP 내부 파일별 독립 다운로드 URL은 제공하지 않습니다. 파일명이 다른 양식·여러 후보가 있는 양식은 연결 실패로 남길 수 있습니다.
- 기존 저장 보고서는 재작성하지 않습니다. AI와 백엔드 변경 반영 후 새 보고서부터 적용합니다. 추가 모델 호출은 없습니다.


## 후속 수정: 서류명·링크만 표시

사용자가 실제 보고서에서 제보한 평탄화된 포상 제출서류 표, 깨진 수요조사 기한, 날짜 뒤 문의처 제목 혼입을 회귀 사례로 추가했습니다. 앞의 카드/담당자 표시는 새 보고서에서 사용하지 않습니다. 서류명에 실제 양식 URL만 연결하고, ZIP이면 이름에 `(ZIP)`을 표시합니다. 연결하지 못한 서류는 이름만 남깁니다. 서류 종류로 사내 담당자를 추천하던 로직은 제거했습니다.

- 번호 목록 분리, 부수·서식 번호 제거, 표 머리글/지시문 후보 제외
- 월·일 유효성 및 날짜 범위 검증, 섹션/파일 경계에서 구절 수집 중단
- 확인한 짧은 서류명·URL이 같으면 표시 중복 제거
- AI 668개, 백엔드 321개, 프론트엔드 11개 테스트 통과
- 프론트엔드 빌드 통과. 린트 오류 없음, 기존 DocumentsPage 경고 2개 유지
- 운영 템플릿의 로컬 메일 HTML과 API 모킹 웹 화면을 Playwright에서 검증. 390/320px 메일 넘침 없음. 외부 이메일 전송은 하지 않음
- 보고서 생성 시 추가 LLM 호출 없음. 원문 OCR/파싱 누락 복구나 의미적 사실 검증을 보장하지 않음. 실제 공고의 전반적인 정답률은 별도 검수 필요
