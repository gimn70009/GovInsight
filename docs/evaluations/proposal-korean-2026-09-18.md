# 제안서 초안 한국어 문체 오류 조사 (2026-09-18)

## 관찰한 오류

사용자 로그는 항목 개수 검증 이후 한국어 문체 검증에서 실패했다. 첫 생성과 문체 보완 모두 2번 항목의 첫 문장을 `non_formal_or_incomplete`로 판단했고, 보완 대상은 2·3·4번 항목이었다. 로그에 생성 본문을 남기지 않기 때문에 해당 실패 문장 자체는 확인하지 못했다.

## 확인한 결함과 수정

일반 큰따옴표와 작은따옴표 안의 마침표를 인용된 문구의 일부가 아닌 문장 끝으로 분리하는 오검출을 재현했다. 예를 들어 `당사는 "기술거래기관 지정. 운영계획"이라는 항목에 맞춰 작성합니다.`를 중간에서 잘라 불완전한 문장으로 거부했다.

닫힌 일반 따옴표의 범위도 기존 괄호·곡선 인용부호와 같이 보호한다. 실제 문구·수치·사실·계획은 변경하지 않는다. 영어 소유격·이름 내부 아포스트로피는 구분하며, 닫히지 않은 인용부호와 인용 밖의 미완성·명사형 문장은 여전히 거부한다. 분량·항목·회사 근거 검증과 호출 한도는 유지한다.

이 결함이 사용자 로그의 정확한 원인이었다는 증거는 없다. 수정 전 실제 모델 재실행에서도 생성이 성공했으므로 원래 오류가 반복 재현됐다고 보고하지 않는다.

## 실제 모델 확인

- 사용자 제공 [KIAT 공고](https://www.kiat.or.kr/front/board/boardContentsView.do?MenuId=b159c9dac684471b87256f1e25404f5e&board_id=90&contents_id=37ceab1394c849f38e4db7bea1532c6d)는 자동 접근에서 차단 페이지를 반환했다.
- [산업통상부 공식 공고](https://www.motir.go.kr/kor/article/ATCLc01b2801b/71313/view)의 신청서식 HWPX와 공고문 HWPX를 현재 파서로 읽었다. 신청서식은 88,070바이트, 추출 본문 7,375자, 제목 후보 211개였다. KIAT 파일과 바이너리 동일성은 검증하지 못했다.
- 실행 중 FastAPI의 판별 API도 같은 4개 제목을 반환했다: `사 업 계 획 서`, `Ⅰ. 일반현황`, `Ⅱ. 사업추진 여건`, `Ⅲ. 사업 추진 계획`. 선택 항목의 의미적 적절성을 이번 수정에서 변경하거나 보장하지 않는다.
- 테스트용 간단한 양식 1건과 공식 양식 재실행에서는 수정 전에도 생성이 성공했다.
- 수정 후 실행 중 FastAPI의 `/internal/monitoring/proposal-write`에 공식 공고문·양식 본문으로 요청했다. gpt-5-mini 응답은 `COMPLETED`, 4개 항목, 약 27.97초였다. 최종 본문 길이는 641·592·647·1,026자였다.
- 서버 응답까지만 확인했으며 사용자 브라우저 표시와 Spring Boot·Oracle 저장 경로는 이번 검증에 포함하지 않았다. 이 소수 실행은 전체 성공률을 의미하지 않는다.

## 회귀 검증

- 기존 생성 응답 구조 테스트 13개에 따옴표 관련 테스트 13개를 추가했다.
- AI 전체 588개 테스트 통과.
- 변경 Python 파일 4개 린트 통과.
- 자동 테스트는 실제 외부 모델을 호출하지 않는다. 위 실제 모델 확인은 별도의 수동 재현 요청이다.


## 후속 수정: 문체 보완 실패로 전체 초안을 폐기하지 않음

추가 사용자 로그에서는 3번 항목의 문체를 보완한 응답이 400자 미만이 되어 전체 생성이 실패했다. 문체 규칙은 초안의 권장 품질로 취급하고, 모든 항목의 분량·항목 대응·근거 ID·작성 안내문 금지 검증을 통과한 원본을 먼저 확보하도록 변경했다. 이후 문체 보완이 짧아지거나 다시 실패하면 보완 본문을 버리고 원본과 제출 전 표현 검토 안내를 완료 응답으로 전달한다. 초기 필수 검증 실패는 계속 차단한다. 전체 실행 시간 한도와 영문 검증 정책은 변경하지 않았다.

이 후속 변경은 실제 모델을 추가 호출하지 않고 사용자 로그와 같은 실패 경로를 대체 응답으로 재현했다. AI 전체 597개 테스트와 변경 파일 린트가 통과했다. 앞의 실제 모델 성공 기록은 이 후속 변경 이전의 실행이다.
