# 긴 원문 근거 선택 및 보고서 추출 검증

## 확인한 원인과 변경

- 기존 분석 도구는 본문의 앞 70%·뒤 30%를 남겼고, 첨부는 앞 파일부터 분량을 소진했습니다. 중간 조건과 뒤쪽 첨부가 모델 입력에서 빠질 수 있었습니다.
- 절/문단·완전한 줄/문장 단위의 키워드 기반 선택과 파일별 분량 배분으로 변경했습니다. 원문 자체를 인용 구간으로 전달하며 요약을 다시 요약하지 않습니다.
- 보고서 추출은 별도 결정적 코드입니다. `신청대상 → 역 할`을 실제 대상처럼 수용하고 다중행 서류를 첫 줄만 가져오는 문제를 합성 사례로 재현했습니다. 머리글·빈 서식·작성 예시를 걸러내고 다음 표제 전의 조건/서류를 함께 읽습니다. 첨부파일명은 끝의 문서 용도·확장자를 보존합니다.

## 검증 결과

- `ai/`에서 `.venv/Scripts/python.exe -m pytest -q`: **650개 통과**.
- 중간 기한·예외, 서로 다른 기한 보존, 뒤 파일 원문 보존, 중복 파일, 극소 예산, 분할 불가 조건, 빈 근거 차단, 잘못된 표 값, 여러 줄 서류, CRLF, 긴 파일명 및 URL 보존을 검증했습니다.
- 신규 및 변경 운영 코드·관련 개별 테스트의 Ruff 검사 통과. 기존 `test_analysis_graph.py`에는 작업 전부터 있던 줄 길이(E501) 위반 17개가 남아 있습니다. 해당 파일의 새 줄 길이 위반은 제거했으며 기존 전체 회귀 테스트는 통과합니다.
- `ai/`에서 `.venv/Scripts/python.exe scripts/evaluate_evidence_selection.py`: 핵심 구절을 반복 배경문 중간에 둔 합성 문서 6건(각 약 72,000자), 4,000자 예산에서 기존 선택은 핵심 구절 0/6, 새 선택은 6/6 보존했습니다. 새 선택 결과는 약 2,800자입니다. 60회 측정의 선택 처리 시간은 로컬 평균 4.61ms, p95 5.13ms였습니다. 시스템 상태에 따라 달라집니다.
- 합성 평가는 위치 편향 재현용이며 실제 공고의 정답률, 근거 적중률 일반화, 환각 감소율, 전체 LLM 지연/토큰 비용을 측정한 값이 아닙니다. 외부 모델 API나 실제 발송은 호출하지 않았습니다.
- 백엔드·프론트엔드 코드는 변경하지 않았으며 이번 작업에서 해당 모듈 테스트는 재실행하지 않았습니다.

## 남은 한계와 다음 평가

- 키워드가 없거나 표 파싱이 잘못된 경우 근거를 놓칠 수 있습니다. 생략 여부와 원문 위치는 입력 추적 정보이며 모든 출력 주장에 대한 의미 검증이 아닙니다.
- 보고서 서버 전달 한도(본문 80,000자, 첨부 파일당 40,000자/합계 120,000자)는 기존과 같습니다. 이 범위 밖의 내용은 보고서 추출기가 확인할 수 없습니다.
- 파싱·분류 오류 및 이미 저장된 분석은 자동 보정하지 않습니다. 기존 분석 재사용 및 보고서 보존 정책을 유지합니다.
- 실제 공고 20~30건을 사람이 검수해 대상/기한/제출처/서류 정답과 원문 위치를 기록하고, 필드별 정답·오답·보류율, 근거 보존율, p50/p95 전체 지연, 모델 호출/입출력 토큰을 기존 버전과 비교하는 것이 다음 단계입니다. LLM judge는 보조 평가로 사용하고 임베딩 유사도를 사실 정답으로 간주하지 않습니다.
