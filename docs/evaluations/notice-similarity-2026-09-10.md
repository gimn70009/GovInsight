# 유사공고 검색 개선 검증 — 2026-09-10

이 문서는 소규모 개발 자료의 전후 비교다. 운영 환경의 일반적인 정확도나 대규모 API 응답 시간을 보증하지 않는다.

## 평가 자료와 판단 범위

- 실제 저장된 공고 11건의 모든 조합 55쌍. Codex가 추출 원문과 저장 분석을 검토한 초기 라벨이며 사용자·독립 전문가 검수 전이다.
- 동일 사업의 다른 기관 게시 2쌍: 에너지공기업 기술나눔(KIAT/산업통상부), 지역산업위기대응 이차보전 2차 변경(KIAT/산업통상부).
- 목적이 다른 52쌍. 같은 기관·연도·제조 분야라는 이유만으로 유사하다고 평가하지 않는다.
- 규제특례 승인 결과와 승인기업 사업화 지원 1쌍은 관련성이 있으나 기능 범위 판단이 필요해 지표에서 제외한다.
- [고정 평가 자료](../../backend/src/test/resources/similarity/real-notices-20260910.json)에 공개 제목·URL·원문 발췌·저장 목적·요약 및 실제 임베딩 코사인을 보관한다. 연락처는 제거했다. 업체별 비공개 회사 분석이나 제안서는 포함하지 않는다.
- 변경 전은 직전 미확인 어휘 오탐 수정까지 적용된 선정 규칙이다. 변경 후 기준을 같은 자료를 보며 개발했으므로 독립 평가셋이 아니다. 임의로 만든 정답을 실제 전문가 라벨로 취급하지 않는다.

## 계산 성능

동일 JVM에서 기존/새 순위 계산을 20회 준비 실행 후 60회 교대로 측정했다. 정규화된 특징과 새 코드의 문서 통계는 캐시된 조건이다. 100/1,000/5,000건은 실제 11건의 특징을 반복한 합성 부하로, 실제 대규모 공고 데이터가 아니다. DB·네트워크·벡터 생성/파싱·캐시 구축 시간은 이 표에서 제외한다.

| 후보 수 | 기존 p50(ms) | 변경 p50(ms) | 기존 p95(ms) | 변경 p95(ms) |
| ---: | ---: | ---: | ---: | ---: |
| 100 | 0.559 | 0.264 | 1.361 | 0.453 |
| 1,000 | 1.744 | 0.553 | 3.087 | 1.120 |
| 5,000 | 4.761 | 1.005 | 6.034 | 1.309 |

실제 로컬 API는 공고 11건에서 첫 조회 207.780ms, 반복 40회 p50=26.116ms, p95=44.832ms였다. 이 측정은 localhost의 프론트 프록시·인증·Oracle 조회·JSON 응답을 포함하며 변경 전 API 시간과의 직접 비교는 아니다.

## 비용과 기존 데이터

- 신규 분석은 기존 임베딩 생성 단계의 입력만 정리한다. 조회할 때 추가 LLM/임베딩 호출은 없다.
- 기존 11건을 한 번의 임베딩 요청으로 복구하는 데 3.23초가 걸렸다. 입력은 2,099자에서 2,151자로 늘었다. 목적을 복구한 영향이며 비용 감소를 주장하지 않는다. 청구 토큰·금액은 측정하지 않았다.
- 검색 프로필·벡터·모델명·수정 시각만 트랜잭션으로 갱신했다. 원문이나 분석이 작업 중 바뀌면 취소하도록 비교했다. 분석·비교 데이터·제안서 해시가 전후 동일했고 실제 저장 상세 API 6건도 동일했다.
- DB 변경 없이도 기존 벡터와 새 선정 기준을 사용할 수 있다. 미확인 입력으로 만든 과거 벡터는 의미 점수만으로 후보를 선택하지 않는다.

## 재검증

백엔드에서 `./gradlew.bat test --tests "*SimilarNoticeEvaluationTest"`로 고정된 실제 코사인과 라벨의 양방향 회귀 평가를 재실행한다. 이 테스트는 외부 모델과 Oracle을 호출하지 않는다. `HybridNoticeRankerTest`는 주제 충돌 우회·단일 단어 과대평가·캐시 통계 제외·상위 20개 동점 순서를 검증한다. Java와 Python은 같은 `text-cases.json`으로 미확인 값과 실제 부정 조건 처리를 확인한다.
