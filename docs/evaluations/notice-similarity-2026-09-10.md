# 유사 공고 검색 개선

**핵심:** 공통 안내 문구 때문에 생기는 오탐을 줄이고, 반복 계산을 캐시해 후보 선별 속도를 개선했습니다.

[프로젝트 소개](../../README.md) · [설계 요약](../DESIGN.md)

## 문제와 해결

| 문제 | 바꾼 점 |
| --- | --- |
| “원문에서 확인하지 못했습니다”가 공통 어휘로 계산됨 | 미확인 문장을 제외하고 비어 있는 사업 목적을 원문·저장 요약에서 보완 |
| 일부 선정 경로에서 목적이 다른 공고가 통과함 | 모든 경로에 주제 충돌 검사 적용, 구체적인 공통 근거 확인 |
| 후보마다 같은 특징을 반복 계산함 | 문서 특징·통계 캐시, 상위 후보만 선별 |

조회할 때 추가 LLM·임베딩 호출은 없습니다.

## 정확도: 같은 사업을 찾고 다른 목적은 제외했는가

실제 저장 공고 **11건의 55쌍**을 비교했습니다. 같은 사업 2쌍, 다른 목적 52쌍, 판단 보류 1쌍입니다.

| 항목 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 같은 사업을 양방향으로 검색 | 1 / 2쌍 | 2 / 2쌍 |
| 다른 목적을 잘못 연결 | 0 / 52쌍 | 0 / 52쌍 |

변경 후 결과는 기존 벡터와 입력을 정리한 벡터에서 동일했습니다. **표의 변경 전은 첫 미확인 문구 오탐 수정까지 적용한 상태**로, 최초 문제 발생 버전과의 비교는 아닙니다.

라벨은 Codex가 원문과 저장 분석을 검토해 붙였습니다. 같은 자료로 기준을 조정했고 독립 검수·미사용 평가셋은 없어, 이 결과를 제품 전체 정확도로 일반화하지 않습니다.

## 속도: 순위 계산에 걸린 시간

| 후보 수 | 변경 전 p95 | 변경 후 p95 |
| --- | ---: | ---: |
| 100건 | 1.361ms | 0.453ms |
| 1,000건 | 3.087ms | 1.120ms |
| 5,000건 | **6.034ms** | **1.309ms** |

p95는 측정값의 95%가 이 시간 이내였다는 뜻입니다. 실제 11건의 특징을 반복한 **합성 부하**에서, 같은 JVM으로 20회 준비 실행 후 60회 교대로 측정했습니다. 특징·통계가 캐시된 조건이며 DB·네트워크·임베딩·캐시 구축 시간은 제외했습니다.

## 남은 검증

바꿔 쓴 제목, 다른 연도·차수, 여러 산업이 결합된 사업, 목적이 비슷한 별도 사업을 추가해야 합니다. 독립 검수한 새 자료로 정확도를 확인하고, 실제 공고가 늘어난 환경의 전체 API 지연도 측정할 계획입니다.
