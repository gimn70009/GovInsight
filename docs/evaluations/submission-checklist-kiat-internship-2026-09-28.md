# 제출 서류 체크리스트 실공고 대조 평가

## 결론

2026년 첨단분야 인턴십 지원사업 4차 공고의 실제 저장 결과에는 신청 단계 필수 서류인 **참여기업의 최근 3개년 결산재무제표가 누락**되어 있습니다. 운영계획서·협약서·평가표 및 출석부를 한 항목에서 설명하면서 제출 시점도 섞여 있습니다. 이 사례의 체크리스트는 참고 자료로 사용할 수 있지만, 제출 준비를 완료했다고 판단할 수 있는 완전한 목록으로 쓰기에는 부족합니다.

서류명이 원문에 있다는 사실과 제출 의무·대상·시점이 정확하다는 사실은 다릅니다. 현재 인용 대조 검사는 통과했지만 실제 목록의 누락과 단계 오류는 남았습니다. 한 공고의 저장 결과를 검수한 것이므로 전체 기능의 평균 정확도나 모델의 반복 생성 성공률로 일반화하지 않습니다.

## 수치로 말할 수 있는 범위

| 측정 항목 | 결과 | 해석 |
|---|---|---|
| 저장된 항목의 원문 인용 대조 | 2/2 통과 | 인용 문자열이 원문에 있다는 뜻이며 의미적 정답률이 아님 |
| 신청서류 표의 최상위 필수 서류명 포함률 | **1/2 = 50%** | 사업계획서와 결산재무제표 두 행만 분모로 사용. 사업계획서 내부 별첨은 별도 행으로 중복 계산하지 않음 |
| 문서별 제출 시점이 섞인 저장 항목 | 1개 | 운영계획서·협약서·평가표/출석부 혼합 |
| 평가 공고 수 / 저장 결과 수 | 1 / 1 | 전체 평균 정확도·정밀도·재현율 또는 반복 안정성 추정 불가 |

50%는 **이 공고의 명시적인 신청 필수 서류 두 종류에 한정한 포함률**입니다. 기능 전체 정확도가 50%라는 뜻이 아닙니다. 회사·대학·학생의 서로 다른 의무와 신청·협약·운영 단계를 한 분모에 섞어 단일 정확도로 계산하지 않았습니다.

## 보완 전 코드상 검증 범위와 실제 재현

1. ai/app/domains/analysis/proposals/drafting.py의 지시는 제출서류 표를 빠짐없이 읽고 필수·조건부·선택·권장, 신청·협약·운영 단계를 구분하도록 요구합니다. 그러나 누락 없음은 지시일 뿐, 완전성 검사를 구현한 것은 아닙니다.
2. 같은 파일의 _verified_items는 해당 본문 또는 첨부에서 정규화한 source.excerpt 문자열이 발견되는지 검사합니다. 항목의 서류명·필수성·적용 대상·단계·설명이 그 인용으로부터 타당하게 도출되는지는 판정하지 않습니다.
3. _supplement_missing_submission_files는 특정 이름의 ZIP 안에서 찾은 파일명을 조건 확인이 필요한 후보로 추가합니다. 일반 HWP/PDF 본문의 제출서류 표를 정답 목록으로 만들고 모델 결과와 전수 대조하는 기능은 없습니다. 이 공고에는 ZIP이 없으므로 재무제표 누락을 보완하지 못합니다.
4. 현재 모델 출력의 제출서류 상한은 15개입니다. 긴 공고에서는 별도의 완전성 제약이 되지만, 이번 저장본은 2개뿐이므로 이번 누락을 목록 상한 탓으로 설명할 수 없습니다.
5. 저장 본문·첨부로 현재 _build_proposal_source_context(..., 32000)를 재실행했습니다. 결과 JSON은 30,283자이며 재무제표, 사업자등록증, 기관소개 자료, 협약·평가 관련 구절이 포함됩니다. 이것은 현재 입력 구성의 재현이며, 저장 당시 실제 모델 입력 로그를 복원한 것은 아닙니다.
6. 실제 저장본에 _retain_verified_source_references와 _normalize_preparation_structure를 다시 적용해도 두 항목과 단계가 그대로 남습니다. 재무제표 누락과 단계 혼합을 현재 후처리가 탐지·보완하지 못함을 확인했습니다.

따라서 이번 결과를 원문 파싱 실패나 현재 입력 길이 제한만으로 설명할 근거는 없습니다. 모델의 항목 선택·묶음·해석과, 이를 보완하지 못하는 검증 범위를 우선 검토해야 합니다.

## 개선 우선순위

에이전트의 탐색 횟수를 늘리는 것보다 **명시적인 제출서류 표의 항목과 생성 결과를 대조하는 검증**이 우선입니다. 신청 필수 두 행 누락 방지, 별첨 포함 관계, 기관별 조건, 제출 시점이 다른 문서의 분리를 이 사례의 회귀 기준으로 삼을 수 있습니다. 필수 서류 수를 무조건 늘리거나 첨부파일 존재만으로 제출 의무를 확정해서는 안 됩니다.

전체 품질을 평가하려면 별도의 실제 공고 표본에서 사람이 정답 목록을 만들고, 문서명·제출 주체·수신처·조건·단계를 함께 대조해야 합니다. 누락과 과잉 포함을 별도로 집계하고, 생성 실패와 추출 불가능한 첨부도 평가 대상에서 숨기지 않아야 합니다.
