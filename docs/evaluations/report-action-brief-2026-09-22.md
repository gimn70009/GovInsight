# 보고서 제출 안내 본문 검증 (2026-09-22)

## 변경 범위

- 기존 긴 요약·참여 의견을 제목, 기관, 문서 유형, 변경 상태, 기회점수, 짧은 요약, 제출 주체·기한·방법·서류·문의 담당, 첨부 및 원문 링크로 정리했습니다.
- 보고서 요청에 저장 원문·비교 요약·첨부 URL과 파싱 텍스트를 연결했습니다. 모델 재분석 및 외부 발송을 추가하지 않았습니다.
- HTML 이스케이프와 HTTP(S) 링크 검증을 적용하고, 텔레그램은 보이는 텍스트 길이 기준으로 검사합니다. 원문 다운로드 URL의 쿼리는 보존합니다.

## 검증

- 백엔드 Gradle 전체 테스트: 312개 통과, 실패·오류·건너뜀 0개. 저장된 버전의 원문·비교 요약·첨부 링크 전달, 실패한 첨부 파싱의 링크 유지, HTML 이스케이프, 이메일 링크, 텔레그램 HTML 요청을 검증했습니다.
- 보고서 Python 테스트 16개 통과. 기한의 시간·시간대, 복수 국가/경로, 문의와 제출처 구분, 첨부와 필수 서류 구분, 구버전 데이터의 대체 표시, 안전한 URL, 표시 UTF-16 및 저장 길이, 생략 안내를 확인했습니다.
- 프론트엔드 빌드·기존 테스트 11개 통과, 린트 오류 0개(기존 DocumentsPage 경고 2개).
- 실제 템플릿에서 생성한 가상 예시 보고서를 대체 API로 상세 화면에 표시했습니다. 데스크톱 1440px 및 모바일 390px에서 첨부 링크의 주소·새 창 열기·가로 넘침·기존 수신자/재전송 흐름을 검증하고 캡처를 직접 확인했습니다.

- AI 디렉터리에서 전체 테스트 634개 통과. 저장소 루트 실행 시 설치된 uuid_utils가 선택되어 호환성 테스트 1개가 실패했으나, 모듈 디렉터리 실행으로 로컬 호환 모듈을 사용해 해결했습니다. 관련 코드는 수정하지 않았습니다.
- 종료 시 8080 포트를 비웠습니다.

## 한계

- 실제 Telegram/SMTP 메시지를 보내거나 외부 첨부파일을 내려받지 않았습니다. 다운로드 URL은 수집된 원본 주소이며 기관 사이트 인증/세션/만료 제약은 그대로 적용됩니다.
- 제출 정보는 명시적인 원문 구절 및 기존 분석의 기한·대상을 조합합니다. 복잡한 표나 긴 문맥, 입력 한도를 넘는 부분은 추출하지 못할 수 있으며 추정 대신 원문 확인을 표시합니다. 사내 담당자 배정 기능은 추가하지 않았습니다.
- 보고서 길이 한도를 초과하면 축약 및 생략 건수를 표시합니다. 기존에 저장된 보고서는 바뀌지 않으며 새 보고서 생성부터 적용됩니다.
- Telegram 형식 참고: https://core.telegram.org/bots/api#html-style


## 메일 시각적 위계 후속 개선

- 실제 메일이 모든 줄을 같은 크기로 표시하던 부분을 메일 전용 HTML 템플릿으로 분리했습니다. 카드 제목·기관/분류/점수·제출 안내·첨부 링크를 각각 다른 시각적 위계로 표시합니다.
- 기존 텍스트 메일과 저장된 본문을 유지하며 HTML만 렌더링합니다. 새 메일 서식은 서버 반영 후 발송 시 적용되고, 추출 문구 변경은 새로 생성한 보고서부터 적용됩니다. 별도 LLM 호출은 없습니다.
- ▷·▶ 글머리표와 줄바꿈된 제출처/문의처 처리를 추가하고 문의처를 제출처로 잘못 합치지 않는 테스트를 확인했습니다.
- 실제 운영 코드 `ReportEmailTemplate.render`가 생성한 HTML을 Gradle 테스트 산출물로 저장하고 Python Playwright로 렌더링했습니다. 긴 한국어 제목·파일명, 링크 7개의 주소 보존, 840px 데스크톱 및 390/320px 화면 가로 넘침, HTML 주입 방지를 확인했습니다.
- `backend`에서 `gradlew.bat test` 후 저장소 루트에서 `ai/.venv/Scripts/python.exe frontend/tests/reportEmail.browser.py`로 재현할 수 있습니다. 예시 링크는 example.go.kr이며 브라우저의 외부 HTTP(S) 요청을 차단합니다. 캡처는 `DELIVERY_SCREENSHOT_DIR`로 지정할 수 있습니다.
- 실제 Gmail·네이버 수신함 렌더링 및 외부 메시지 발송은 수행하지 않았습니다. 저장된 문서 유형의 정확성, 복잡한 원문의 제출처/문의처 추출 한계는 남아 있습니다.

- 후속 최종 검증: 백엔드 318개·AI 636개 테스트 통과, 관련 Ruff 및 diff 검사 통과. 8080 점유 PID만 정리하고 포트 비움을 확인했습니다.
