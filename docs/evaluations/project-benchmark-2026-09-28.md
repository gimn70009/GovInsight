# 실공고 정확도·시간·한계 안내 측정 — 2026-09-28

현재 코드로 KIAT 공고 20건을 실제 수집·분석하고 보고서 제출 안내를 생성했다. 운영 DB는 읽기 전용으로 조회했으며, 평가 결과를 운영 DB에 저장하거나 알림을 발송하지 않았다. 기능 코드는 이번 측정에서 변경하지 않았고, 기존 `fix/submission-checklist-accuracy` 브랜치의 미커밋 보고서 변경을 포함한 작업 트리를 평가했다.

측정 결과, 사업 제안 체크리스트를 재사용하는 방향은 타당하지만 재사용 원본에도 필수 서류 누락·조건 오류·중복이 남아 있다. 별도 보고서 추출에서는 모델이 찾은 서류까지 검증 단계에서 제거되는 문제가 재현됐다. 첨부 길이뿐 아니라 모델의 여러 차례 호출, 분석 재시도, 제안 생성 시간이 지연에 기여한다.

## 평가 범위와 해석

- 표본: KIAT 사업공고 게시판의 연속 공고 20건. 무작위·다기관 표본이 아니다. 직접 첨부 61개, 내려받을 수 있었던 ZIP 내부 항목 50개를 조사했다.
- 모델: 현재 환경의 `gpt-5-mini`, 실제 회사 프로필, 분석 한 번당 120초·최대 2회, 근거 수집 원문 한도 본문/첨부 각각 40,000자. 제안 240초. 보고서 30초.
- 기준 목록: 모델의 서류 목록을 보기 전에 게시글과 읽을 수 있는 첨부의 신청 단계 목록을 검수했다. **Codex의 1차 검수이며 독립적인 사람 검수를 거친 정답셋이 아니다.** 문서군 단위로 비교하고, 선택 가능한 대체 서류는 한 묶음으로 취급했다. 신청자 유형별 목록은 합집합이다. 따라서 151개를 모든 신청자가 모두 내야 한다는 뜻이 아니다.
- 포함률은 `기준 목록에서 결과에 대응되는 문서군 수 / 기준 문서군 수`다. 별도 출력 행으로 합쳐진 여러 서류는 내용이 명시된 경우 각각 인정하고, 동일 서류의 중복 행은 분자에 한 번만 반영했다. 부분 제목도 연결된 실제 양식으로 식별 가능하면 같은 문서군으로 인정했다.
- 이름이 맞더라도 필수성·조건·주체·제출 시점·대체서류 설명까지 맞았다는 뜻은 아니다. **포함률을 종합 정확도나 정밀도로 부르면 안 된다.** 이 평가에서는 전 항목의 의미 정밀도를 단일 수치로 산정하지 않았고, 확인한 오류를 별도로 기록했다.
- 스페인 접수 안내 1건은 국내 제출 의무를 별도의 2026년 3월 모공고에 위임하고 있어 완전한 기준 목록을 확정하지 못했다. 포함률 분모에서 제외했다. 한독 공고는 국내 제출목록만 대조했다. 미지원 원본 내부의 모든 요구사항, 표·스캔의 파싱 정확성, 업종 전체의 정확도는 검증하지 않았다.
- 아래 보고서 포함률은 **화면의 6개/축약 3개 표시 제한 적용 전 내부 목록** 기준이다. 화면에 일부만 표시된 현상으로 설명되는 누락만 센 것이 아니다.

## 1. 제출서류 정확도

| 측정 대상 | 결과 | 해석 |
|---|---:|---|
| 자연스러운 실행에서 사업 제안이 생성된 체크리스트 2건 | 17 / 19 문서군, 89.5% | 작은 표본의 이름 포함률. 조건 오류와 중복은 따로 존재 |
| 보고서 내부 제출서류 목록 19건 | 40 / 151 문서군, 26.5% | 30초 실패로 목록이 비어 있는 5건을 포함 |
| 보고서 모델 호출이 실패하지 않은 평가 대상만 | 40 / 82 문서군, 48.8% | 시간 초과를 제외해도 누락이 남음 |
| 기준 서류가 있는 18건 중 모두 반영한 사례 | 1건 | 특구 후보과제 공고의 5종 목록 |
| 서류 제출 없이 온라인 설문을 작성하는 공고 | 빈 목록으로 일치 | 0/0을 100%로 합산하지 않음 |

20건의 공고 분석은 모두 결과를 반환했다. 그중 실제 회사 적합성·유형 판정으로 사업 제안이 생성된 것은 11번과 16번의 2건이었다. 나머지를 체크리스트 생성 실패라고 집계하지 않았다. 단, 해당 공고들의 보고서 제출 안내는 별도 추출 경로이므로 그 경로의 결과를 원문과 비교했다.

확인한 오류:

1. **산업융합 규제샌드박스 사업화 지원(11번)**: 필수 제출목록의 `사업계획서`가 제안 체크리스트에 없다. 그 목록을 재사용한 보고서에도 없다. `외주용역 활용계획서`는 실제 서식 설명에 근거가 있지만 외주용역 사용 조건이 있는 항목인데 필수로 표시됐다.
2. **한독 2+2 공동기술개발(16번)**: 협정서·LOI·전체 기관이 서명한 영문계획서 중 하나를 제출하는 요구가 빠졌다. 일반 영문계획서 항목의 상세 설명에도 그 서명 조건이 없다. 국문계획서·신청자격 확인서는 조건부로 표시됐고, 참여의사 확인서와 정보동의·서약서는 필수/조건부로 중복됐다. 연구소 인정서에 원문 제출목록에서 확인되지 않은 `또는 면제 사유 문서`가 붙었다.
3. **인턴십(3번), 보고서 별도 추출 진단**: 추가 진단 실행에서 모델은 사업계획서와 결산재무제표 두 항목을 추출했다. 재무제표의 조건을 세미콜론으로 연결해 반환했고, 조건 전체가 원문의 연속 문자열과 같아야 한다는 검증에 걸려 서류 자체가 제거됐다. 모델의 서류 발견과 최종 사용자 목록 사이에서 누락이 발생했다.
4. **기획형 규제샌드박스(15번)**: 본문에서 필수인 중소·중견기업 확인서에 다음 행의 `필요시 제출` 조건이 붙었다. 별도 진단 재실행에서는 두 묶음의 서류를 반환했으나 제출 의무 표현이 인용 범위에서 빠지고 조건 인용도 맞지 않아 모두 제거됐다. 진단 결과는 위 주 측정값에 섞지 않았다.

이전에 보완한 인턴십 제안 생성도 실제 모델로 별도 실행했다. 이 공고는 정상 흐름에서는 제안 생성 조건을 충족하지 않아, **구성요소 진단에서만 그 조건을 우회했다. 운영 화면에는 저장하지 않았다.** 65.65초 후 기준 신청 서류 5종을 모두 포함했지만, 재무제표가 중복됐고 평가기준을 근거로 `직무기술서 및 멘토링 운영계획서`를 필수 서류로 추가했다. 해당 인용만으로 별도 필수 제출서류라고 확정할 근거는 부족했다. 5/5 포함을 전체 정확도 100%로 해석할 수 없다.

성능 해석 제한:

- 격리 `TwoStageAnalysisWorkflow`를 동시 2건으로 실행한 20건 묶음은 849.26초였다. 실제 서비스는 기본 분석과 조건부 제안을 배치 단계별로 나누므로 이 값을 운영 모니터링 전체 완료시간으로 부르면 안 된다. 임베딩, DB 저장, HTTP 콜백, 외부 발송 시간도 포함하지 않았다.
- 보고서는 공고별 요청을 최대 3개 동시에 실행했다. 20건이 한 요청의 전체 60초 제한을 공유하는 부하 시나리오는 측정하지 않았다.
- 첫 보고서 실험은 원문 전체를 AI 모듈에 전달했다. 이후 **실제 Java `ReportAttachmentExcerpts` 함수**를 실행하여 백엔드와 같은 발췌를 적용했다. 모델 입력이 달라진 1·2·10·16번만 새 입력으로 재측정했고, 다른 16건은 입력 payload가 동일함을 확인했다. 최종 수치는 교정된 입력의 첫 결과를 사용했다. 초기 실험의 7건 실패는 최종 5건 실패와 구분해야 하며, 차이가 입력 축소만의 인과 효과라고 주장하지 않는다.
- 같은 프로세스의 보고서 캐시를 측정한 값이다. 변경 없는 공고의 DB 분석 재사용을 포함한 모니터링 전체 재실행 시간은 아니다.

## 3. 처리 한계 안내

| 상황 | 실제 표본 | 현재 안내 경로 및 한계 |
|---|---:|---|
| 첨부 전체 실패 | 4개 | 실행 경고 및 상세 첨부 실패 표시 경로 있음. 3개 크기 제한, 1개 ZIP 파싱 오류 |
| 직접 첨부 미지원 형식 | 4개 | 상세에서 `내용 분석 미지원`. 실행 경고 집계는 FAILED만 포함하므로 이 4개는 같은 경고 수에 포함되지 않음 |
| 성공 처리된 ZIP 내부 미지원 | 8개 | 부모 ZIP은 COMPLETED. 상세 첨부 행에서 `내용 분석 완료`로 보이며 내부 미지원 파일을 같은 행에서 구별하지 않음 |
| 긴 원문 생략 | 공고 6 / 20건 | 분석 도구의 coverage에는 기록되지만 구조화된 전체 분석 coverage가 사용자 화면으로 이어지는 계약은 없음 |
| 보고서의 처리 한계 | 문서별 메타데이터 부족 | 보고서 첨부 DTO에는 파일별 parseStatus·오류·ZIP 내부 상태가 없음. 보고서 템플릿은 파일별 읽기 실패나 전체 입력 생략률을 정해진 항목으로 표시하지 않음 |

전체 61개 중 53개가 COMPLETED였다는 것은 파서가 텍스트를 반환했다는 뜻이다. 모든 페이지·표·조건이 올바르게 추출됐거나 모델이 전부 읽었다는 증거가 아니다. 가장 긴 사례는 첨부 추출 텍스트 752,141자 중 39,301자(약 5.2%)가 첫 시도 근거 도구에 선택됐다. 생략은 참고자료 비중이 큰 사례여서, 이 비율을 정확도 손실률로 해석하면 안 된다.

주의사항 검토에는 추출 텍스트가 없는 첨부의 개수를 알리는 보완이 이미 있다. 따라서 모든 실패 안내가 전혀 없다는 결론도 부정확하다. 다만 ZIP 부분 미지원, 긴 입력 생략, 보고서별 한계 안내는 서로 연결되지 않은 부분이 있다.

경고 화면은 이번에 실제 운영 데이터를 새로 저장하여 브라우저에서 재현한 것은 아니다. 실제 수집 상태와 DTO·화면 코드 경로를 대조하고 기존 경고 저장·조회 테스트로 확인했다.

## 다음 수정 우선순위

1. 서류명은 원문으로 확인됐는데 조건 문자열 형식 때문에 항목 전체가 사라지는 경로를 보완한다. 검증을 일괄 완화하지 않고 표 제목·행·조건 근거를 나눠 검증하고, 조건을 확정하지 못하면 항목을 남겨 확인 필요로 표시하는 정책을 검토한다.
2. 명시된 제출목록과 최종 체크리스트를 대조하는 범위를 넓히고, 필수성·대체서류·중복을 함께 확인한다. 현재 단일 공고 보완 규칙은 다른 형식의 표와 모델의 모든 오판을 해결하지 못한다.

### 남은 정확도 문제

- 새 인턴십 제안에는 기관소개 자료와 사업자등록증을 묶은 중복 항목이 남았다. 인용은 기관소개 자료만 명시한다. 일부만 대응하는 묶음의 기존 보존 정책 때문에 삭제하지 않았다.
- 새 한-독 제안은 기준 11개 문서군을 모두 복원했지만, 협정서·사업자등록증·회계증빙의 묶음/별칭 세 행이 추가로 남았다. 그중 법인등기부등본의 제출 의무는 해당 인용에서 확인되지 않았고, 회계증빙 별칭은 필수로 남아 정확한 표 기반 면제 조건과 충돌한다. **누락 개선이 모든 중복·근거 없는 추가 항목까지 해결한 것은 아니다.**

- 긴/인식 불가 표, 읽지 못한 첨부, 모델이 놓친 항목, 부분 묶음과 동의어는 남은 과제다. 전체 정밀도·종합 정확도 수치는 부여하지 않았다.

## 후속 수정: 제안 없는 보고서의 원문 목록 보완과 실패 시 보존

최신 정상 사업 제안이 없는 공고도 보고서에 전달된 본문·첨부에서 제출표를 대조한다. 신청 단계의 확인된 항목을 우선 배치하고 기존 AI 인용 검증을 통과한 다른 이름을 보완한다. 같은 이름의 원문 행은 대상·조건을 보존하며, 같은 행에 실제로 있는 모델의 조건 구절만 함께 유지한다. 최신 정상 제안의 재사용 경로는 그대로 유지했다.

모델 실패·시간 초과·설정 오류·비활성화에서도 확인된 목록과 수집된 양식 링크를 표시한다. 보고서에는 이름·링크만 표시하고, 원문에서 복구한 부분 목록에는 전체 제출서류 목록을 원문에서 확인하도록 안내한다. 캐시된 모델 출력도 현재 요청의 원문과 다시 대조하므로 추가 모델 호출은 없다. 동시 처리 수·모델·프롬프트·입력 예산·시간 제한은 바꾸지 않았다.

기존 표 파서의 연결만으로는 실제 시간 초과 공고 9·20번을 복구하지 못했다. 9번은 공고의 접수방법이 `[붙임1] 신청서식`의 작성·제출을 명시하고, 해당 단일 첨부의 신청 문장 아래에 번호가 있는 첨부서류 목록이 있었다. 보고서 경로에 이 명시적인 연결 형식을 추가해 사업계획서, 확약서, 사업자등록증, 직전회계연도 재무제표, 중소기업 또는 중견기업 확인서 5개 문서군을 복구했다. 파일명이나 빈 양식 제목만으로 제출 의무를 만들지는 않는다. 관련 증빙자료처럼 구체성이 없는 항목, 미연결·중복 번호, 조건부로만 요청한 신청서, 참고·선정/협약 이후 자료와 잘려서 예외가 숨겨진 행은 자동 확정하지 않는다.
