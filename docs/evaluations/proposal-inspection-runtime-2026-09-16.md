# 양식 확인 전체 실패 재현 및 복구

## 확인한 원인

로컬 브라우저에서 모든 첨부가 “확인하지 못한 파일”로 표시됐다. backend 직접 요청과 Vite 프록시를 통한 HTTP 요청은 정상 응답했지만, 브라우저에서는 양식 판별 HTTP 요청이 한 건도 전송되지 않았다.

브라우저에서 실제 로드된 API 모듈을 확인하니 `api.inspectProposalSource`가 undefined였으며 호출 시 `TypeError: m.api.inspectProposalSource is not a function`이 발생했다. 디스크의 client.ts에는 이 함수가 있었지만 실행 중인 Vite의 `/src/api/client.ts` 응답에는 없었다. 화면 컴포넌트는 새 버전이라 구 API 모듈과 함께 실행되면서 각 파일의 오류가 공통 UNAVAILABLE 상태로 변환됐다.

개발 서버 재시작 후 함수와 HTTP 요청이 정상적으로 제공됐다. 변경 감지 누락이 발생한 정확한 OS 이벤트는 추적하지 못했으므로 Git 전환이 직접 원인이었다고 단정하지 않는다.

## 보완

- Windows의 개발 서버에 1초 간격 파일 감지를 적용해 파일 교체 감지 누락 가능성을 줄인다.
- 5173이 사용 중일 때 다른 포트로 자동 실행하지 않도록 strictPort를 적용한다.
- 모델의 분류 정책, 수집·다운로드 동시 처리, 초안 생성 알고리즘은 변경하지 않았다.
- [Vite 파일 감지 설정](https://vite.dev/config/server-options.html#server-watch)은 개발 전용이며 polling은 파일 확인 비용을 추가한다.

## 실제 브라우저 확인

로컬 저장 공고의 첨부 본문과 실행 중인 AI 서비스를 사용해 Chromium에서 사업 제안 탭을 열었다. 모의 API가 아닌 실제 판별 응답을 확인했다.

| 공고 | 판별 요청 수 | 표시된 양식 카드 | 확인 실패 |
| --- | --- | --- | --- |
| 국가첨단전략산업 투자지원금 사업 수정 공고 | 7 | 4 | 0 |
| 독일 등 유럽 진출 희망 중견기업 지원사업 | 4 | 2(국문 신청서·영문요약) | 0 |
| 산업융합 규제샌드박스 사업화 지원 하반기 공고 | 2 | 1(사업계획서 및 제출 서류 서식) | 0 |

13건 모두 HTTP 200이며 WRITABLE 또는 NOT_WRITABLE 응답이었다. 브라우저 pageerror는 0건이었다. DOCX·XLSX 미지원 표시는 기존 지원 형식에 따른 결과로 변경하지 않았다.

이 검증은 전체 실패 현상의 복구 확인이다. 판별된 각 항목의 의미 정확도나 초안 본문 생성·재작성 성공률을 검증한 결과가 아니다. 특히 투자지원금 서식의 표·수치 입력칸과 하반기 양식의 목차성 제목이 후보에 포함된 결과는 별도 내용 검토가 필요하다. 사용자 제공 외부 링크는 웹 도구에서 열리지 않아, 이번 확인은 앱에 이미 수집된 해당 공고의 본문을 사용했다.

## 설정 변경 검증

- 실행 중인 Vite에 임시 모듈을 요청한 뒤 파일 내용을 교체하고, 재요청에서 새 내용을 제공하는 동작 확인. 임시 모듈은 제거했다.
- 실제 API 모듈 응답에 inspectProposalSource가 포함됨을 확인했다.
- 프론트엔드 11개 테스트와 빌드 통과. 린트 오류 0개, 기존 경고 2개.
