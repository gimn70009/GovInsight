## 재현

Python Playwright와 Chromium이 필요하며 현재 프로젝트 AI 가상환경과 설치된 Chromium을 사용했습니다. 캡처는 기본 `frontend/dist/delivery-checks`에 저장하며 `DELIVERY_SCREENSHOT_DIR`로 변경할 수 있습니다.

## 한계

- SMTP 전송은 대체 `JavaMailSender` 및 클라이언트로 검증했습니다. 실제 Gmail·네이버 계정 인증·외부 SMTP 전송·메일함 도착은 확인하지 않았습니다.
- 브라우저 검증은 모든 애플리케이션 API를 대체 응답으로 처리했습니다. 캡처의 이름·주소·발송 내역은 테스트 데이터입니다.
- 실제 Oracle DB에 연결하거나 테이블을 생성·초기화하지 않았습니다. `ddl-auto=none`으로 운영하는 기존 DB는 신규 이메일 테이블·시퀀스를 준비해야 합니다.
- Gmail/네이버 OAuth 연결, 첨부파일, 열람 추적, 프로세스 장애 뒤 자동 큐 복구는 포함하지 않습니다.


## 후속 UX 개선 검증

- 발신 미설정 상태의 자동 발송 스위치를 클릭하면 계정 설정 창이 열리고, PUT 요청 없이 꺼짐 상태를 유지하는지 확인했습니다.
- 미설정 상태의 수신자 테스트 버튼도 동일 안내로 연결되며 실제 테스트 발송 요청이 발생하지 않습니다.
- 설정 재조회 결과가 계속 미설정인 경우의 안내, 조회 실패 표시, 설정 완료 이후에도 자동 활성화되지 않는 동작을 확인했습니다.
- 창 안의 `자동 발송 켜기`에서 저장 실패 시 꺼짐을 유지하고, 재시도 성공 후 창이 닫히며 새로고침 후에도 켜짐이 유지되는지 확인했습니다.
- 수신자 체크박스는 서버 저장 이후 선택 상태를 반영하고 기존 수신자 CRUD·실패 재전송 흐름을 유지합니다.
- 미설정 상태의 데스크톱·모바일 화면과 관리자용 설정 방법을 연 모바일 창을 캡처해 확인했습니다. 별도 경고 배너와 중복 하단 설정 줄은 제거했습니다.
- 이번 프런트엔드 변경에서 빌드·기존 테스트 11개·린트 오류 0개(기존 경고 2개) 및 확장 브라우저 시나리오를 확인했습니다. 백엔드 코드는 변경하지 않았으며 앞의 306개 테스트 결과는 이전 구현 검증 기록입니다.
