# 실제 공고 기반 보고서 누락 보완 검증

## 범위

KIAT 양자-스페인 접수 안내의 공개 국문 PDF, 제출서류 ZIP, 참고자료 ZIP을 내려받아 파서와 보고서 모델 입력을 확인했다. KIAT 상세 HTML은 접근 차단으로 확보하지 못했다. 운영 DB에 저장된 해당 실행 요청을 재생한 검증은 아니다. 개인정보가 있는 운영 로그, API 키, 이메일/Telegram 발송은 사용하지 않았다.

## 확인한 문제와 수정

- 백엔드가 앞쪽 첨부부터 120,000자 예산을 소진하여 뒤쪽 안내문 텍스트가 빠질 수 있었다. 파일당 40,000자 한도 내 균등 배분과 남는 용량 재배분으로 변경했다.
- 보고서 입력은 공고·접수 안내 우선, 양식은 짧은 내용과 이름, 참고자료는 이름만 모델에 전달한다. 참고자료는 안내/필수서류 검증 근거에서 제외한다.
- PDF의 한 줄로 합쳐진 페이지에 레이아웃 추출을 추가한다. 정상 페이지는 기존 빠른 추출을 사용하며 저장된 이전 파싱 결과는 자동 갱신하지 않는다.
- 표 머리글만 신청 자격으로 표시하지 않고, 선행 물결표 마감일·시간·시간대와 국가별 접수 행을 보존한다. 예산 단위가 섞인 마감일은 거부한다.
- 값이 원문에 직접 있거나 검증된 인용의 순서 있는 발췌 조합이면 표시한다. 인용 주변의 잘못된 표기 때문에 실제 원문 값까지 전부 삭제하지 않는다. 이것은 의미적 함의 검증이나 완전한 조건 검증은 아니다.
- 저장 체크리스트를 모델의 정답으로 취급하지 않는다. 서류와 조건을 다시 추출하고 실제 양식 이름으로 URL을 연결한다. 모델 목록이 비면 접수 절차에 명시된 계획서 등 최소 서류를 보존하되 전체 목록 확인 안내를 남긴다.
- 확인서/신청자격 서식 이름 매칭과 실제 ZIP URL 연결을 보완했다. 참조 링크를 새로 만들어내지 않는다.

## 실제 모델 점검

자동 테스트와 분리하여 공개 첨부만으로 호출했다. nano minimal/low는 표·인용·필드 누락이 남았다. mini low는 27.2초 호출에서 더 많은 근거가 남았으나 별도 호출은 30초 제한에 걸렸다. 최종 mini minimal은 한 건에서 22.0초에 주관/공동기관 자격, 한국 접수 마감, K-PASS와 문의 연락처를 추출했다. 이는 단일 사례의 시간이며 평균/P95 측정이 아니다. 최종 결과에서 빠진 스페인 접수 행과 동시 접수 조건은 별도의 원문 행 보존 회귀로 보완했다.

짧은 접수 PDF에는 전체 제출서류 표가 없다. 첨부된 양식 파일이 있다는 사실만으로 모든 서류를 필수로 확정하지 않았다. 운영에 전달된 본문/첨부가 충분하지 않은 경우 전체 서류 목록은 여전히 확인이 필요하다. 직접 안내된 연구개발계획서 접수는 최소 서류로 보존한다. 게시글 상세 HTML을 포함한 전체 목록 정확도 평가는 수행하지 못했다.

## 자동 검증 및 적용

- AI 전체 724개 회귀 테스트 통과, 변경 Python 파일 Ruff 통과.
- 백엔드 전체 340개 테스트 통과. 첫 실행에서 기존 초안 조회 순서 테스트 1건 실패 후 관련 코드 변경 없이 전체 재실행에서 통과했다.
- 외부 모델을 호출하는 코드는 자동 테스트에 포함하지 않았다. 실제 Oracle 저장, 화면, 이메일/Telegram 도착은 확인하지 않았다.
- 기본 모델은 gpt-5-mini, minimal. 1회/공고, 30초/공고, 60초/작업, 캐시 정책은 유지한다. 시간 초과 시 기존 기본 보고서 처리로 진행한다.
- 기존 환경변수의 REPORT_BRIEF_MODEL 설정이 우선한다. nano가 명시되어 있다면 mini로 변경해야 한다. 백엔드/AI 서버 재시작과 새 보고서 생성이 필요하며 이미 저장된 보고서 재전송은 내용을 바꾸지 않는다. PDF 개선은 새 파싱부터 적용된다.
