## 결론과 조사 범위

- 저장된 신청자격은 양자산업협력(version 2), 연구기획과제(version 4), 소부장 총괄기관(version 12)의 3건이다. 2+2+5=9개 저장 문장 모두 현재 입력 지문과 일치하고 Java 화면 투영에도 남는다.

### 8. 미래자동차 매출·연구개발비 기준의 각주 누락 — 높음

실제 HWPX 1쪽에서 매출 비율 50% 또는 연구개발비 비율 3% 조건에 연결된 각주는 산정 기간을 2025년 4분기~2026년 3분기로 명시하고 부품·기술 범위를 정하는 조문·별표를 안내한다. 이 두 각주는 DB 추출 텍스트에 있지만 최종 선택 입력에는 없다. 연구개발비 산정기준의 세 번째 각주는 남는다.

`ParticipationRawSources`가 `1)`, `2)`를 새 절 제목으로 분리하고, 분리된 각주가 후보 선별·전송에서 빠진다. 수정은 부모 조건과 각주 연결을 보존하는 구조부터 해야 한다. 조건·숫자만 더 많이 추출하라는 프롬프트로는 입력 누락을 복구할 수 없다.

최종 입력은 8,740바이트로 20,000바이트 상한보다 작다. 양자산업협력도 11,700바이트이며 상한 초과가 이번 누락 원인은 아니다. 미래자동차의 50%/3%, 기업집단 제한, 80점 기준, 제재 조건 자체는 입력에 남아 있다. 저장 결과가 없으므로 화면 누락이나 실제 최종 오분류로 확정하지 않는다.

### 9. 뿌리산업 대학 공고의 모집 문맥 오인 — 보통, 결과 영향 미확인

원본 1쪽의 ‘외국인 유학생 모집제한 권고대학 … 신청 제한’이 모델 입력의 `[공고 대상]`으로 잡혔다. `ParticipationRecruitmentContext`의 패턴이 모집 행위와 모집제한을 구분하지 않고 첫 일치 문장을 선택한다. 실제 모집 제목·도입 문장과 제한 문장을 구별하도록 보완할 지점이다.

다만 실제 자격·신청 제한·지역·기술분야 표는 입력에 보존되어 있다. 이 문맥 오류가 실제 최종 오분류를 발생시켰다고 확정하지 않는다.

## 수정 순서 제안

1. 실제 신청자 원문과 각주가 입력까지 도달하도록 후보 선별·구역 연결부터 보완한다.
2. 동일 1회 추출 안에서 현재 모집 / 신청 주체 / 자격·제외 / 근거 행의 대응을 분명히 한다. 새로운 모델 호출이나 전 공고 재생성이 필요하다고 미리 확정하지 않는다.
3. 주체별 표 행·대체 자격·독립 제외·OR/AND 보존을 실제 실패 사례로 회귀 검증한다. 올바른 문체와 인용 존재만으로 의미 정확성을 대신하지 않는다.
4. 실제 신규 생성 결과의 소수 원본 대조를 거친 뒤 기존 저장 결과의 처리 범위를 결정한다. 이번 분석에서 운영 데이터를 보정하지 않았다.
5. 마지막으로 본문/설명 반복을 정리한다.
