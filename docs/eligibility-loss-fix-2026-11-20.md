## 변경

- Python은 긴 추출본의 번호형 구역 경계를 인식하고, 신청요건 아래의 표·인력·각주를 유지한다. 지원내용·선정규모·유의사항 아래에도 실제 신청/수행 제한·선행 선정·역할별 역량·인력 조건이 있으면 문단과 연결된 주석을 입력 후보로 보존한다. 각 선택 구간은 원본의 연속된 문자열이며 서로 떨어진 구간에는 구분자를 넣는다.
- 낮은 우선순위 후보를 일괄 제외하던 동작을 수정한다. 직접 신청 자격을 먼저 선택하고, 별도 수혜자 역할 및 절차·첨부 목록 제외는 유지한다.
- 단일 호출의 원문 상한은 8,000→32,000 UTF-8바이트, 프롬프트·스키마를 포함한 입력은 20,000→48,000바이트, 출처는 24→64개, 출력은 4,096→8,192토큰, 추출 항목은 32→64개다. 실제 입력·출력 비용은 늘 수 있다. 모델/low·호출 1회·재시도 0회·호출 120초/문서 150초 제한은 유지한다. 레거시 파이프라인의 예산 기본값은 변경하지 않는다.
- 프롬프트에 중복 신청/수행, 선행 선정, 인력 구성별 최소 인원·경력·자율 여부, 확정 제외의 의미 보존을 명시한다. 특정 공고의 숫자나 정답을 지시하지 않는다.
- `required_rows`를 2열 신청자격 표에서 3·4열 인력/구성 표와 명시적인 대상 기관의 역할별 문단까지 확대한다. 본문뿐 아니라 해당 행을 직접 인용한 정상 세부 설명도 대응으로 인정한다. 합계만 남고 구성별 수치가 빠지면 `APPLICANT_ROW_UNCOVERED`로 기록하고 해당 출처의 조건은 검토 필요로 남긴다. 숫자 존재 검사는 수치의 적용 주체나 모든 의미 관계까지 검증하지 않는다.
- Java 표시용 구역 추적은 `[문서 전체 텍스트 추출]`에서 이전 시각 판독의 구역을 초기화한다. 제출서류 등 행정 제목으로 정상 사업명을 덮어쓰지 않는다. 기존 request와 캐시 키를 유지한다.
