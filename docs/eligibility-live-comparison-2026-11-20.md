# 신청자격 수정 후 실제 모델 비교 (2026-11-20)

## 결론

이번 1회씩의 실제 생성 결과에서 **누락 포함 완전 반영률은 35.2%(31/88) → 28.4%(25/88)**로 내려갔다. 창업도시는 개선됐지만 창업패키지와 스마트제조가 나빠져 이번 수정을 전체 품질 개선으로 판정할 수 없다. 기존 결과를 새 응답으로 덮어쓰지 않았다.

## 비교 기준

- 이전 `manual-checks-final.json`의 89개 검사항목을 고정했다. 원문 날짜가 충돌한 v4-C07은 이전처럼 제외하여 분모는 88개다.
- 기존 저장 결과의 실제 표시와 새 원응답 → Python 검증 → Java 투영 → 현재 프런트 표시 함수의 최종 문자열을 비교했다. 실행 중인 서비스의 DB를 바꾸거나 브라우저 화면을 배포하지 않았다.
- 본문과 정상 세부 설명, 적용되는 공통 조건을 함께 읽는다. 숫자·주체·AND/OR·의무/자율·예외를 보존해야 완전이다. 정확한 원문 인용만 있고 표시문이 ‘원문 확인’으로 바뀌면 그 본문은 반영으로 세지 않는다. 검토 상태여도 화면에 남은 정상 설명은 채점한다.
- PDF 원본의 인력 표·도시 구성·제외 조항·클라우드 구성과 이전 감사 원문 기록을 다시 대조했다. v7 업무별 인원은 각 1인 수치가 있어도 원문의 전담·겸직 자율 구분을 전담인력으로 한정하여 부분으로 판정했다.
- 단일 표본 실행이며 모델의 평균 성공률을 추정하는 실험이 아니다. 비교점수는 고정 체크리스트의 완전 반영률이며, 새로 생성된 모든 문장의 정밀도나 신청서류/OCR 정확도는 아니다. 추가 오류는 별도로 기록한다.

## 실제 실패 단계

1. **입력 선별은 넓어졌지만 아직 누락이 있다.** 스마트제조 `s13`의 원문에는 ‘데이터 수집·활용 체계가 미흡한 기업 → 데이터 수집·검증 우선 → AI공장 연계’가 있다. Python의 문단 선택은 유형 선택·지원조건 표만 남기고 이 문장을 잘랐다(v6-S13). 바이트 상한만 늘려서는 이 조건을 복구하지 못한다.
2. **주된 사업별 누락은 모델 생성 단계다.** 스마트제조는 선택된 43개 출처 중 12개 출처만 본문/설명에서 인용했고, 상생 일반형/AX선도 기관 역할, 자동화공정, DX멘토단, 제조데이터, R&D 조건들이 실제 입력에 있으면서 원응답에서 빠졌다. 비인용 31개 모두가 독립 누락 조건이라는 뜻은 아니지만, 판정표의 해당 사업 조건들은 직접 확인했다. 세 응답 모두 `unresolved_source_ids=[]`였다.
3. **새 누락 검사가 정상 본문도 가린다.** 초기 패키지의 ‘총괄 1인·조직장 1인·전담 2인’은 모델이 `s10 L2-L4`의 원문 문단을 인용해 올바르게 생성했다. 검증은 같은 내용의 표 행 L9-L12를 직접 인용하지 않았다는 이유 등으로 4행을 미대응으로 처리한다. 해당 출처의 모든 본문을 검토 필요로 바꾸므로 정상 인원 본문까지 화면에서 사라진다. 도약의 필수 1·1인, 창업도시 대표도시·전담인력 본문도 이 출처 단위 처리의 영향을 받는다. 누락 탐지와 정상 조건 보존을 조건별로 분리해야 한다.
4. **의미 변형이 검증을 통과한다.** 창업패키지와 스마트제조의 확정 제외를 ‘제한/제외될 수 있음’으로 약화했다. 클라우드 단독형/통합형의 구성·기업 규모·각주 적용 범위도 섞였다. 새 프롬프트의 보존 지시만으로 해결되지 않았다.

창업도시에서는 10개 자치단체 이름, 유형 선택, 부산·세종 예외, 추진단장, 지방재원, 정규직 최소 3명(총괄책임자 제외), 경력 5년 이상 최소 3명 등이 정상 설명에 남아 점수가 올랐다. 반면 연접 2개 시 대안, 협력도시 상한, TIPS 필수, 겸직 허용, 전남광주 운영기관·중앙정부 협의는 입력에 있으면서 모델이 빠뜨렸다.
