# 신청자격 프롬프트 실제 API 검증 — 수정안 미채택 (2026-11-19)

## 결론

범용 판단 규칙을 보강한 프롬프트 2개를 실제 공개 공고 3건에 각각 적용해 총 6회 호출했다. 두 안 모두 표 자격 누락·잘못된 항목 생성이 남아 채택하지 않았다. 이번 프롬프트 변경만 실험 전 상태로 원복했고, 이전에 구현한 원문 복구·근거 검사와 기존 저장 결과는 보존했다. 이번 검증에서 운영 DB 쓰기는 0회다.

실제 API 테스트는 완료했지만 신청자격의 일반화 수정이 완료됐다는 결과는 아니다. 회귀 테스트 통과, JSON 형식 통과, 실제 원문 의미 일치는 구분한다.

## 무엇을 바꿔 시험했나

- 1차: 현재 신청 대상 확인 → 자격/제외/우대 분류 → 주체별 근거 연결 → 누락·반복 점검 순서를 명시했다.
- 2차: 접수 준비는 필수여도 자격이 아니라는 기준, 서류 목록에서 자격을 추론하지 않는 기준, 표의 각 행·대안·각주 보존을 더 구체적으로 명시했다.
- 특정 공고명·기관명·공고 ID·정답 수치는 넣지 않았다. 출력 스키마, 모델, 추론 강도, 기존 후처리와 호출 제한은 바꾸지 않았다.
- 실패한 실험안은 운영 코드에 남기지 않았다. 새 키워드 후처리로 실패 응답을 정답처럼 고치지 않았다.

양자산업협력은 **프롬프트 구분 능력 확인용 대조 입력**이다. 정상 선택 입력의 실제 지원 대상에 원문에 존재하는 제출서류·조달계약 예외 구역을 추가했다. 정상 운영 선택기가 이 두 구역을 그대로 전송했다는 의미가 아니다. 미래자동차·총괄주관 공고는 정상 선택 입력을 사용했다. 별도 모집 참고 대상은 기존 코드가 이미 제외했으므로 이번 결과만으로 프롬프트가 그 혼입을 해결했다고 판단할 수 없다.

각 실험안의 공고별 호출은 1회다. 반복 안정성·전체 공고 정확도·실험 전 프롬프트 대비 개선율을 측정한 실험은 아니다. 실험 전 프롬프트의 같은 입력 실시간 대조 호출은 하지 않았다.

## AI 원응답과 기존 검증 코드의 차이

| 실험 | 공고 | AI 생성 항목 | Python 채택 항목 | Java VERIFIED 항목 |
| --- | --- | ---: | ---: | ---: |
| 1차 | 양자산업협력 | 2 | 1 | 1 |
| 1차 | 미래자동차 | 4 | 4 | 4 |
| 1차 | 총괄주관 | 6 | 6 | 6 |
| 2차 | 양자산업협력 | 2 | 1 | 0 |
| 2차 | 미래자동차 | 6 | 6 | 0 |
| 2차 | 총괄주관 | 5 | 5 | 0 |

양자산업협력의 잘못된 서류 자격 1개는 두 번 모두 기존 `DOCUMENT_LIST_NOT_QUALIFICATION` 검사에서 걸러졌다. 이것을 프롬프트 추출 성공으로 계산하지 않는다. 1차의 표 누락·절차 오분류는 기존 검증을 통과했다. 따라서 `READY`와 `VERIFIED`는 의미상 완전성의 보장이 아니다.

2차 채택 항목은 모두 합니다체/완결 문장 기준에서 `review_required`가 되었고 Java도 해당 항목을 검토 필요로 투영했다. `READY` 응답 안에도 검토 필요 항목이 있을 수 있다. Java 투영 결과를 파일로 확인했으며 이번 작업에서 실제 브라우저 화면을 새로 검사하지는 않았다.

## 호출 범위·출처·사용량

## 다음 수정에서 해결해야 할 지점

1. **표의 행과 결과 항목의 대응:** 현재는 표 전체가 한 출처여서, 한 문장만 인용해도 전체 표가 처리된 것으로 보일 수 있다. 행별 입력 식별과 출력 대응을 검증할 수 있는 구조를 검토해야 한다. 행 누락을 문장 키워드 추가만으로 해결하지 않는다.
2. **자격과 안내의 구분:** 신청자의 지위·능력 조건과 모집 규모·지정 기간·접수 준비를 구분하는 판단을 검증해야 한다. 법적 등록과 전산 등록을 섞지 않아야 한다.
3. **대안·각주 보존:** 각 대안과 각주가 어느 본문 조건에 반영됐는지 확인해야 한다. 인용이 존재하는 것만으로 설명의 완전성을 판단하지 않는다.
4. **평가 기준 분리:** 실제 생성의 의미 정확성·누락과 형식/근거 검증을 따로 측정한다. 수정에 사용하지 않은 다른 공고와 반복 호출을 포함하기 전에는 일반화 성공으로 보고하지 않는다.

이 항목들은 이번에 새로 구현한 기능이 아니라 실제 실패로 확인한 후속 과제다. 실패 결과로 운영 DB를 덮어쓰지 않았다.

## 로컬 검증과 증거

신청자격 회귀 테스트 387개와 Ruff를 통과한 실험안도 실제 의미 검증에는 실패했다. 복원 후에도 신청자격 테스트 387개와 Ruff가 통과했다. 코드의 실험 전 상태 일치, 문서의 시스템 지시문 일치 및 8080 포트가 비어 있음도 확인했다. 이번에는 백엔드 제품 코드를 바꾸지 않았으며 기존 Java 투영을 6개 실제 응답에 실행했다. 백엔드 전체 1,819개 및 브라우저 테스트 통과 기록은 이전 작업 기록이고 이번 실행으로 재표기하지 않는다.

로컬 증거는 Git에서 제외되는 `backend/build/eligibility-prompt-live-20261119/`에 있다. `manifest.json`, `tested-prompt.txt`, 공고별 `provider-result.json`/`response.json`/`guide.json`은 1차, `round-2/`의 동명 파일은 2차다. `public-download-verification.json`에는 공개 원본 검증이 있다. API 키·내부 추론 내용은 기록하지 않았다. 최종 JSON 응답·근거 입력은 로컬 검증 산출물로 보관하고 전체 원문을 로그에 출력하지 않는다.

명확한 판단 지시와 실제 평가를 구분하는 구성은 [OpenAI 프롬프트 안내](https://developers.openai.com/api/docs/guides/prompting) 및 [추론 모델 안내](https://developers.openai.com/api/docs/guides/reasoning-best-practices)를 참고했다. 이 문서의 품질 판정은 위 실제 공고 응답과 원문 비교에 따른다.
