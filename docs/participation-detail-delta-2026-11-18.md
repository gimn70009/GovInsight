# 본문·세부 설명의 반복 수정

## 원인

제보 공고는 `2027년도 소재·부품·장비 양산성능평가지원사업 총괄주관연구개발기관 모집 공고`의 2026-11-18 13:10:14 수집본(version 12)이다. 현재 입력과 저장 캐시 키가 일치했고 저장된 8개 항목 자체에 겹치는 설명이 있었다. 화면은 서버의 본문/설명을 각각 표시한다. 기존 중복 검사는 공백을 제외한 전체 문장 동일 여부만 확인하므로 어순이 다른 재진술과 본문 일부의 반복이 통과했다. 이전 개별 보정본과 새 수집본은 별개다.

협회·단체의 비영리법인·주무부처 등록 설명은 본문에 모두 포함돼 있다. 기업지원기관 설명은 대부분 같지만 연구기관·대학 제외가 추가 정보이므로 전체를 삭제해서는 안 된다. 같은 원문을 인용한 설명이라도 법적 범위·증빙·예외가 추가될 수 있다.

## 수정

- 프롬프트와 생성 스키마의 `details` 설명에 추가 정보만 작성하고 없으면 빈 배열로 반환하도록 명시했다. [OpenAI 공식 지침](https://developers.openai.com/api/docs/guides/reasoning-best-practices)의 짧고 직접적인 지시 원칙에 맞춰 기존 문구를 대체했다.
- 서버는 본문 전체 또는 연속된 완결 문장과 정확히 일치하는 설명만 생략한다. 완전한 의미 비교나 한국어 동의어 판정은 하지 않는다. 숫자·부정·주체가 다른 설명과 새로운 정보가 섞인 설명은 유지한다.
- 본문이 검토 필요로 표시되지 않는 경우 설명을 중복으로 숨기지 않는다. 표시 생략 후에도 모든 인용·출처와 저장 캐시는 유지한다.
- 현재 공고만 원문 대조 후 세부 설명을 보정했다. 협회·단체, 의무 불이행, 서류 부합/허위 기재 항목에서 반복 설명 4개를 제거했다. 기업지원기관 설명은 `기업지원기관 신청 구분에는 연구기관 및 대학이 포함되지 않습니다.`로 정리했다. 본문 8개와 연구기관 설명 2개·확인 방법·원문 근거를 보존했다.

## 비용과 실제 생성 한계

기존 gpt-5-mini·low·문서당 최대 1회·재시도 0회·출력 4,096토큰·원문 8,000바이트·전체 입력 20,000바이트·캐시 v6는 유지했다. 최종 코드의 같은 입력 비교는 선택 5구역이 동일하며 직렬화 예산 14,443→14,448바이트, 로컬 o200k_base 계산 3,988→3,987토큰이다. 실제 청구 입력과 로컬 계산은 다를 수 있다.

실제 검증은 중간 프롬프트로 단 1회 수행했다. 입력 3,967·출력 2,492·합계 6,459토큰, 29초, 정상 종료, 11항목을 반환했다. 그러나 재진술·동어 반복 및 별도 모집 조건 혼입이 남아 성공으로 평가하거나 저장하지 않았다. 이후 중복 지시를 `details` 필드에도 직접 배치한 최종 버전은 모의 검사와 비용 검사만 수행했고 실제 모델 효과는 미검증이다. 이 변경이 모든 의미 중복을 자동으로 없앤다는 보장은 없다.

현재 화면의 수정은 이 원응답이 아니라 원문을 대조한 기존 8항목의 세부 설명 보정이다. 대상 행을 잠근 뒤 제목·수집시각·키·기존 JSON이 그대로인지 확인하고 1행만 변경했다. 저장 전후 백업과 별도 연결 재조회가 완료됐으며 다른 공고·원문·본문·캐시 키는 바꾸지 않았다.
