# 신청 자격 누락·분류 감사 — 2026-11-18

현재 DB의 14개 공고를 읽기 전용으로 조사했다. 자격 생성 결과가 저장된 공고는 **소재·부품·장비 총괄주관연구개발기관 모집 공고 1개**였다. 이 공고에서 현재 모집 대상 혼입 1유형(2개 항목), 요약 누락 2유형을 확인했다. 별도로 다른 3개 공고에서 실제 모델 호출 전에 원문이 빠지는 입력 선택 문제를 재현했다.

이는 전 공고의 정확도나 오류율을 측정한 결과가 아니다. 저장 결과가 없는 13건을 자격 추출 실패로 계산하지 않는다. 해당 기능은 상세 조회 시 생성할 수 있으므로 결과 부재만으로 실패 원인을 단정하지 않는다.

## 조사 범위와 방법

- 수집본: 14건 모두 `2026-11-18 15:54:54.1624541`. 감사 스냅샷은 16:15경 확보했다.
- JDBC `SET TRANSACTION READ ONLY`로 본문·첨부 추출 텍스트·기존 자격 응답·분류 자료를 읽고 rollback했다. Spring Boot는 기동하지 않았다.
- 현재 Java 코드의 원문 후보 → 입력 식별자 → 전송 원문 → 저장 결과의 화면 투영을 재생했다. Python은 `select_sources()`만 실행했다.
- 제보 공고는 저장 키가 현재 입력 지문과 일치하며, 저장 9항목이 화면용 결과에서도 9항목이다. 잘못된 2항목은 모두 `VERIFIED` 상태의 신청 주체 항목이다.
- 추가 유료 API 호출 0회, DB 변경 0건, 제품 코드 변경 0건. 진단용 스크립트와 문서만 추가했다.
- 최초 제보의 스마트제조 통합공고는 **현재 DB 목록에 없다**. 과거 보정 결과를 현재 결과로 간주하지 않았고 이번에 재생성하지 않았다.
- 저장된 추출 텍스트를 대조했으며 28개 첨부 원본 전체를 다시 내려받거나 시각 판독하지 않았다. 실제 브라우저 화면을 새로 열어 생성하지 않았으므로 메모리 캐시 상태는 이번 감사 대상 밖이다.

## A. 제보 공고에서 확인한 실제 결과 오류

대상: `2027년도 소재·부품·장비 양산성능평가지원사업 총괄주관연구개발기관 모집 공고`, 현재 version 12, 첨부 23.

### A1. 별도 모집의 신청자 2개가 현재 모집 자격에 섞임 — 우선 수정

원문 제목과 안내는 총괄주관연구개발기관을 현재 모집하며, 세부주관연구개발기관(기업)은 2027년 1월 별도로 모집한다고 명시한다. 현재 신청자격 표에는 협회·단체 / 연구기관 / 기업지원기관의 3개 구분이 있다.

그러나 표시되는 신청 주체는 5개다. 추가된 2개는 사업 개요의 ‘아. 세부과제 지원유형’ 표에서 가져온 **일반·DX 유형 주관연구개발기관 및 공동연구개발기관**이다. 별도 세부과제의 수요·공급기업과 대학 등을 현재 총괄기관 모집 자격과 나란히 보여 준다.

근거: [첨부 23의 모집 안내](../backend/build/eligibility-audit-20261118/attachment-23.txt) 112~117행, 추진체계 138~140행, 참고 표 162~167행, 현재 신청자격 170~177행. 저장 응답의 4·5번째 항목은 `source_ids=[s10]`, `scope=null`이며 화면 투영에서도 그대로 표시된다.

원인: 모집·별도 모집 문맥은 전달되어 있다. 현재 프롬프트에도 다른 수혜자 조건을 섞지 말라는 지시가 있지만 저장 응답이 이를 지키지 않았다. [Java 검증](../backend/src/main/java/com/publicmonitor/backend/domain/document/service/ParticipationRewriteProjection.java)은 source ID와 실제 인용 일치를 검사하고, 해당 인용이 **현재 모집 역할**인지까지 판정하지 않는다. 따라서 진짜 원문을 잘못된 모집에 적용한 항목도 통과한다. 단순히 인용이 존재한다고 의미까지 검증된 것은 아니다.

### A2. 단독 또는 컨소시엄 신청 가능 안내가 요약에서 누락

원문 172행에는 협·단체, 연구기관, 기업지원기관 등이 **단독 또는 컨소시엄**으로 신청할 수 있다고 되어 있다. 선택된 `s11`에도 이 문장이 들어 있다. 그러나 9개 본문과 모든 세부 설명에는 이 선택 관계가 없다.

원인은 모델 추출·요약 단계다. 화면 필터가 생성된 항목을 지운 사례가 아니다. 원문 근거 패널에는 전체 신청자격 구역이 보존되어 있으므로 원문 데이터 손실과는 구분한다. 사용자에게 보여 주는 자격 요약에서 신청 형태가 빠진 문제다.

### A3. 연구기관의 대체 자격 중 전문생산기술연구소가 요약에서 누락

원문 176행은 6개 연구기관 유형을 열거하며, 「산업기술혁신 촉진법」 제42조에 따른 **전문생산기술연구소**를 포함한다. 본문은 일부 유형과 ‘등’으로 요약하고, 세부 설명도 5개 유형만 언급하며 전문생산기술연구소를 빠뜨린다.

선택된 `s11`과 저장 인용에는 이 유형이 그대로 있다. 원문 근거를 펼치면 확인할 수 있지만, 요약만 읽어서는 해당 기관의 자격을 분명히 알 수 없다. ‘신청 불가’라고 잘못 명시한 경우는 아니며 **대체 자격의 요약 누락**이다. 긴 목록의 상세 범위를 설명으로 보존하라는 지시가 결과에 충분히 반영되지 않았다.

### A4. 보존된 조건과 분류 해석

- 협회·단체의 비영리법인·주무부처 등록 조건은 유지된다.
- 기업지원기관에 한정된 ‘연구기관 및 대학 제외’는 해당 항목에 유지된다. 다른 연구기관 구분 전체를 배제한 것으로 보이지 않는다.
- 참여제한, 의무불이행, 유사 기지원 과제, 사업목적·시행계획 요건 미충족의 지원 제외 4항목과 허위기재 관련 세부 설명은 유지된다.
- 일부 제외 조건의 내부 criterion은 SECTOR 또는 EXPERIENCE다. 현재 화면은 EXCLUSION을 별도 ‘지원 제외’ 영역으로 모으므로, 이것을 그대로 ‘업종 항목에 잘못 표시됨’이라고 보고하지 않는다.

## B. 다른 공고에서 재현한 모델 입력 누락

이 3건은 **현재 저장된 생성 결과가 없어 화면의 최종 오류를 확인한 것은 아니다**. 현재 코드가 모델에 보낼 입력에서 필요한 원문을 제외하는 사실을 확인했다.

### B1. 양자산업협력사업: 지원대상 문장 전체 제외

첨부 3의 9행은 동북아 주요 협력국과 사업목적에 부합하는 경제·산업·기술 교류·협력 활동을 수행하는 기관을 지원 대상으로 명시한다.

Java는 이 구역을 보조 source로 복구하고 전송한다. Python의 [selection.py](../ai/app/domains/participation/selection.py) `qualification_heading()`은 제목 전체에서 제외 단어를 찾는다. ‘지원대상 : … 동 **사업목적**에 부합하는 …’처럼 자격 내용을 포함한 긴 제목에서 `사업목적`이 잡혀 자격 제목 인식에 실패하고, 뒤의 `IRRELEVANT.search(heading(source))`가 구역을 탈락시킨다.

그 결과 진짜 지원대상은 빠지고 추진일정·결과발표·선정 후 업무 등이 입력에 남는다. 준비된 6구역의 전체 입력은 11,700바이트로 20,000바이트 상한보다 작다. **예산 초과가 아니라 잘못된 필터 판정**이다.

### B2. 교육 위탁기관: 별표의 시설·인력 기준 제외

대상은 ‘소화물배송대행서비스종사자가 되려는 사람에 대한 교육 위탁기관 신청 공고’다. 첨부 20의 112행이 별표 기준 충족을 신청요건으로 연결한다. 같은 첨부 204~239행에 구체적인 시설·인력 기준이 있다.

현재 선택 입력은 ‘별표 기준을 충족하는 관계기관·단체 또는 법인’ 문장 1개뿐이다. 다음 기준은 입력에 없다.

- 주행실습 교육을 하는 경우: 강사 2명 이상, 이륜차 6대 이상, 실습장 400㎡ 이상, 보험 등.
- 교육강사와 별도로 교육관리자 1명 지정.
- 강사 분야별 자격과 인원, 겸충족 예외 및 영상 활용 예외.
- 시설의 소유·임차와 온라인 교육 시 예외 등.

조건부 기준을 모든 교육 방식에 일률적으로 적용해서도 안 된다. 기준과 예외를 함께 보존해야 한다.

원인은 복합적이다. Java의 키워드·명시 제목 선택에서 별표의 자식 구역이 제대로 연결되지 않고, 같은 이름의 HWPX를 우선하면서 PDF에 남은 상세 구역도 전송에서 빠진다. 전송된 교육관리자·강사 경력 구역 일부는 Python에서 priority 5인데, priority 0~4 후보가 하나라도 있으면 5는 순회하지 않는 규칙으로 배제된다. 전체 입력 6,398바이트이므로 여유가 있어도 빠진다. 프롬프트에 ‘인력·시설을 보존’만 추가해도 해결되지 않는다.

### B3. 미래자동차 전문기업 지정: 매출 기준의 주석 분리·누락

첨부 22의 55~58행에서 매출 비율 50% 또는 연구개발비 비율 3% 요건에 붙은 주석은 산정 기간을 ‘2025년 4분기~2026년 3분기’로 명시하고, 부품·기술의 범위를 정한 규정도 안내한다.

현재 입력에는 ‘신청일이 속하는 분기의 직전 4개 분기’와 비율 요건은 남지만, 구체적인 분기 범위와 부품·기술 범위 주석은 없다. [ParticipationRawSources](../backend/src/main/java/com/publicmonitor/backend/domain/document/service/ParticipationRawSources.java)는 `1)`, `2)` 주석을 독립 제목으로 잘라낸다. 부모 요건과 분리된 주석은 Java의 기준 키워드·명시 자격 제목 검사에서 후보로 살아남지 못하고, 이를 포함한 긴 본문도 최종 선택되지 않는다.

주요 4개 신청 조건은 선택 입력에 남아 있다. 따라서 공고 전체 자격이 사라진 것이 아니라 **산정 기준·범위 설명의 입력 누락**이다. 전체 입력 8,740바이트이며 역시 예산 부족이 원인이 아니다. 생성 결과가 없으므로 매출이 실제로 SECTOR에 표시됐다는 과거 사례를 현재 오류로 재사용하지 않는다.

## C. 참고 관찰 — 확정된 자격 오분류와 구분

- 뿌리산업 양성대학 공고의 모집 문맥 추출은 ‘외국인 유학생 모집제한 권고대학 … 신청 제한’ 문장을 공고 대상으로 잡았다. `ParticipationRecruitmentContext`의 ‘모집’ 패턴이 모집제한 문장에도 일치한다. 자격·지역·기술분야 원문은 입력에 있으나 향후 추출에 잘못된 문맥을 줄 위험이 있다. 생성 결과가 없어 실제 오분류로 확정하지 않았다.
- 연구보안 전담기관은 첨부 8개 중 2개 추출 실패 기록이 있다. 성공한 다른 추출본에 기관·단체, 상근 전담인력 5인 이상, 전용 사무공간 조건이 남아 있으므로 ‘인력조건 누락’으로 계산하지 않았다.
- 1인 창조기업·중장년센터 주관기관 공고의 사업 유형은 제품화·사업화다. 원문은 센터 운영·관리를 위한 프로그램 운영비·인건비 등을 안내하므로 현재 신청자의 역할과 수혜기업 지원 내용을 다시 구분할 필요가 있다. 적절한 대표 유형은 분류 정책에 따라 달라져 확정 오분류 대신 검토 사항으로 남겼다.
- 전체 사업 유형 재생은 분류됨 3건, 별도 공고 성격으로 구분 5건, 검토 필요 6건이다. 검토 필요를 잘못된 유형으로 확정한 것과 혼동하지 않는다.

## 수정 우선순위와 비용 방향

1. **현재 모집 대상과 별도 모집의 역할 연결을 검증**한다. 통합공고의 사업별 자격은 유지해야 하므로 ‘추후/예정’이라는 단어만으로 모든 자격을 삭제하지 않는다.
2. **자격 원문 선택을 먼저 수정**한다. 제목과 내용을 구분하고, 부모 자격의 주석·별표·인력·시설 구역을 함께 유지한다. 관련 조건을 priority 5라는 이유만으로 버리는 동작을 점검한다.
3. **요약의 대체 자격과 신청 형태 누락을 검출**한다. 독립적인 필수·허용 조건이 남아 있는지 확인하며, 검증하지 못한 경우 단순 READY/VERIFIED를 의미적 완전성으로 취급하지 않는다.
4. 중복 세부 설명 정리는 위 문제 이후에 진행한다.

별도 AI 검수 호출이나 전 공고 재생성부터 추가할 필요는 없다. 원문 선택·문맥·출처 연결과 로컬 회귀 사례를 먼저 수정하는 편이 적절하다. 실제 생성 품질은 수정 뒤 필요한 소수 사례로 별도 확인해야 하며, 이번 감사는 이를 실행하지 않았다. 선택 정보를 늘리면 한 호출의 입력량은 달라질 수 있으므로 현재 바이트·출력 상한 안에서 비교가 필요하다.
