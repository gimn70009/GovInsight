# GovInsight AI 모듈 개발 지침

## 적용 범위

- 이 문서는 `ai/` 아래의 모든 파일에 적용한다.
- 루트 `AGENTS.md`의 공통 규칙과 `docs/DESIGN.md`의 기능 설계를 함께 따른다.
- 기능 요구사항과 작업 순서는 각각 `docs/DESIGN.md`, `docs/PLAN.md`에서 관리한다.

## 모듈 책임

- 수집·다운로드·텍스트 파싱·변경 감지는 예측 가능한 일반 Python 코드로 구현한다.
- 문서별 분석 도구 선택과 분석 순서 결정은 AI 에이전트가 담당한다.
- Oracle 저장과 조회는 Spring Boot가 담당하며 AI 모듈에서 Oracle에 직접 접근하지 않는다.
- Spring Boot와의 비동기 HTTP 요청·응답 형식은 `docs/DESIGN.md`를 따른다.

## 에이전트 구성

- LangChain의 에이전트 API와 LangGraph 기반 실행 구조를 사용한다.
- 모델, 도구, 에이전트 실행, 수집·파싱 코드를 서로 분리한다.
- 도구는 하나의 명확한 책임만 가지며 입력과 반환 형식을 타입으로 정의한다.
- 에이전트가 접근할 수 있는 도구와 데이터는 작업에 필요한 최소 범위로 제한한다.
- 도구 호출 횟수, 재시도 횟수와 전체 실행 시간에 상한을 둔다.
- 분석 결과는 스키마로 검증한 뒤 Spring Boot에 전달한다.
- 모델의 내부 추론 과정은 저장하거나 외부 응답에 포함하지 않는다.
- 최종 판단 근거와 실제 도구 호출 기록만 추적 가능한 형태로 남긴다.

## 오류 처리와 테스트

- 하나의 첨부파일 파싱 실패가 가능한 경우 게시글 전체 분석 실패로 이어지지 않게 한다.
- 외부 사이트, 모델 API와 Spring Boot 호출에는 연결 및 응답 타임아웃을 설정한다.
- 테스트에서는 실제 외부 사이트와 모델 API를 호출하지 않고 대체 객체를 사용한다.
- 에이전트의 도구 선택, 결과 스키마 검증, 호출 제한과 실패 처리에 대한 테스트를 작성한다.

## 보안

- 모델 API 키, 토큰, 비밀번호와 개인정보를 Git에 저장하지 않는다.
- 로그에 비밀정보, 게시글 원문 전체, 첨부파일 전체와 모델의 내부 추론을 남기지 않는다.
